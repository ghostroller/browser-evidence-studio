## 1. 设计意图与本次必须解决的问题

### 1.1 产品真正应该完成的闭环

用户正常操作网页并示范任务；应用连续记录可检查的历史现场；用户可以事后回放，补写 checkpoint、需求和字段说明；外部 Agent 定向读取这些资料，产出普通自动化代码；应用进行可重复执行与结果检查；用户看得懂取得了什么、缺了什么及依据是什么；最终脚本离开 Studio 仍能运行。

此前体验不顺的根本原因不是组件或配色，而是把录制 run、浏览器现场、需求、证据和执行状态耦合在一起，迫使用户操作很多内部概念。修改应减少人工搬运 ID、切换控制权和重复示范，而不是增加更多确认页面。

### 1.2 必须落实的用户意图

1. **需求与观察分开**，但可以在 checkpoint 上就地编辑需求，不强迫用户维护独立需求管理系统。
2. **每个 checkpoint 都可注释元素**：从 checkpoint 行进入，选择其历史页面元素，输入注释，绑定到该 checkpoint。
3. **需求 checkpoint 可编辑所需字段**：字段可以不绑定元素；绑定元素可以不写附加注释；字段说明和元素样例各有独立语义。
4. **存档是视频式 DOM 时间轴**：播放、暂停、倍速、跳转、定位 checkpoint；后来也能在完整录制区间新增 checkpoint。
5. **存档后可修改资料并形成版本**：原始事件与资源不改写；Agent 实现和验证引用固定版本。
6. **历史节点能被精确重新定位**，普通原始属性和必要运行状态有据可查；CSS selector / XPath 可生成、解释并验证。
7. **独立业务模块不因无关失败一起中断**；已取得的数据及时落盘；辅助证据失败与业务失败分开。
8. **移除独立“元素”tab**；检查模式有明确目标、蒙版、取消与退出，不能触发网站操作。
9. **减少 Agent 高频操作的人工协助**：在项目授权范围内开放读取、资料草稿、页面探索和试跑；保留真实人工确认与重要外部操作边界。

### 1.3 明确取代的早期建议

| 早期表述 | 本文最终采用的方向 |
|---|---|
| 每个 checkpoint 都必须录制时保存独立完整快照 | 连续录制原件 + 周期完整快照 + 增量事件；checkpoint 是任意可还原时刻的资料标记。可按需生成派生状态缓存。 |
| 需求完全独立维护 | 数据归属项目，创建和编辑入口仍可放在需求 checkpoint 上。 |
| 给需求、checkpoint、注释各暴露一个版本号 | 用户只面对一组任务资料版本 V1/V2/V3；内部另有 schema、草稿修订和节点作用域。 |
| 从回放 DOM 直接复制 selector | 回放用于可视选择；原始信息与历史源结构用于生成和验证定位器。 |
| 失败后继续执行后面所有操作 | 无依赖模块继续；有依赖模块阻塞；取消和不可持久化错误按影响范围停止。 |
| 每次脚本运行都重新人工授权 | 允许任务级开发授权；每次执行仍固定代码、输入和资料版本。 |

### 1.4 非目标

不恢复历史网站的 JavaScript 堆、服务端会话、WebSocket 状态或未加载页面；不通过回放执行真实购买、删除、提交等操作；不承诺任意 Canvas/WebGL/closed Shadow DOM 都能转为 DOM 字段；不引入运行时 LLM 自愈、通用工作流 DSL、第二套 Page API、monorepo 或独立微服务集群。构建工具迁移不是本次主线。

## 3. 数据关系：少量核心对象，清晰的身份与版本

### 3.1 核心对象及职责

| 对象 | 职责 | 生命周期 |
|---|---|---|
| `Project` | 一个相对明确的数据采集任务、环境与工作目录关联 | 长期存在 |
| `BrowserSession` | profile、页面、标签、导航状态、实时控制者 | 独立于录制与执行 |
| `Recording` | 连续采集的事件、源信息、资源引用与缺口 | 录制时追加；封存后不可改 |
| `ReplayPosition` | 一段录制的明确历史状态位置 | 不因播放速度或 UI 变化而改变 |
| `TaskMaterialDraft` | 需求、checkpoint、注释、字段及关联的可编辑草稿 | 乐观并发更新 |
| `TaskMaterialRevision` | 上述资料的一份不可变引用清单 | 发布后不改 |
| `Execution / Attempt` | 某资料版本、某代码与输入的一次执行或尝试 | 历史结果追加保存 |
| `Review` | 独立人工评审，含来源、理由和范围 | 不覆盖机器结果 |

“项目级需求”意味着需求属于业务任务，可由多次示范共同说明；不属于某一张 checkpoint，也不能由脚本随意删减。一个 checkpoint 可关联多个需求，一个需求可关联多个 checkpoint。

### 3.2 最小契约示例

以下类型表达需要保留的语义，正式命名由 T00 根据现有类型收敛，不照搬创建第二套公共契约。

```ts
interface ReplayPosition {
  recordingId: string;
  pageId: string;
  documentId: string;       // 每次文档替换均有新身份
  streamEpoch: string;      // 录制/镜像重新初始化的作用域
  sourceTimeMs: number;     // 原始时间，不是跳过空闲后的显示时长
  eventSeq: number;         // 明确事件边界，消除同毫秒歧义
}

interface HistoricalElementRef {
  position: ReplayPosition;
  frameId: string;
  mirrorScopeId: string;    // 跨 frame ID 变换及 full snapshot 重建的明确作用域
  nodeId: number;
  kind: 'dom-node';
}

interface CheckpointCard {
  id: string;
  kind: 'observation' | 'requirement';
  anchor: ReplayPosition;
  capturedAt: string;       // 指向的原始采集时间
  createdAt: string;        // 资料卡实际创建时间
  derivedFrom?: string;
  title: string;
  notes: string;
  requirementIds: string[];
  annotationIds: string[];
}

interface TaskMaterialRevision {
  schemaVersion: number;
  projectId: string;
  revisionId: string;
  parentRevisionId?: string;
  contentHash: string;
  createdAt: string;
  author: 'human' | 'agent';
  requirementSetRef: string;
  checkpointSetRef: string;
  annotationSetRef: string;
  recordingRefs: string[];
}

interface ExecutionBinding {
  executionId: string;
  materialRevisionId: string;
  materialContentHash: string;
  codeFingerprint: string;
  inputFingerprint: string;
  environmentRef: string;
  mode: 'current-page-test' | 'from-start-validation';
}
```

补充约束：`revisionId` 的存在不等于“用户批准”；确认资料采用独立、不可由 Agent 冒充的审批记录。资料 V 版本与存储 `schemaVersion` 不是同一个维度。UI 不暴露所有内部 ID；Agent API 必须携带精确身份。

### 3.3 简单版本管理（T06）

编辑默认自动保存草稿；每次更新携带 `expectedDraftRevision`，冲突返回明确错误与当前版本，不静默覆盖。对无冲突条目可合并，对同一字段的语义冲突应保留双方修改或要求选择。

保存资料版本、交给 Agent 或创建指定资料的验证时，先生成不可变 manifest，再绑定其 ID/hash。禁止执行只绑定可变 `latest`。版本差异显示新增字段、删除要求、重绑元素、checkpoint 移动和注释变化，不只显示 JSON diff。

回退是“从旧版本建立新草稿”，不是删除新历史。复制 checkpoint 复制卡片及注释编辑内容，继续引用同一原件；默认不复制成另一份同名业务需求。确需独立需求时提供显式“复制为新需求”。从 V1 发布 V2 不修改 V1；旧 Agent 可继续实现 V1，也可读取差异后切换 V2。

已有代码可以重新验证 V2，但需新增执行记录。只增加普通说明可呈现“可能不影响业务实现”的差异提示，仍不能把旧执行改写为新版本通过。

### 3.4 存储建议

沿用原件追加、索引可重建的方向，新增概念性结构如下；路径为建议，可适配现有布局：

```text
recordings/<id>/manifest.json
recordings/<id>/streams/<stream-id>/segments/...
recordings/<id>/source-metadata/...
recordings/<id>/resources-manifest/...
recordings/<id>/gaps/...
blobs/<content-hash>                         # 可共享资源字节
projects/<id>/materials/drafts/...
projects/<id>/materials/revisions/<id>.json
executions/<id>/binding.json
executions/<id>/attempts/...
executions/<id>/datasets/...
```

发布资料版本用原子提交和 hash 校验；索引写失败不反向破坏原件。资源 GC 根据录制、历史资料版本、执行与导出的引用共同决定；仅删除某张卡片不能删除旧版本仍引用的原件。首版不做复杂分支/合并 UI，也不因版本功能强制迁移到数据库。

## 4. 浏览器会话与录制解耦（T01）

**意图：停止保存记录，不应关闭用户的工作现场。**

从现有 `Studio` 中按职责抽取 session 与 recording 生命周期，保持现有 Electron/Puppeteer 连接策略。封存只停止采集、flush、写 manifest 与完整性报告；关闭页面、关闭 profile、退出应用是独立操作。一个 session 可以先后承载多段录制，录制开始前的状态用新 full snapshot 建立基线，不能伪造此前历史。

执行入口明确区分：

- **当前页面试跑**：使用显式 page/document 身份，校验前置状态，保留页面现场；不自动宣称可从零复现。
- **从起点验证**：新建受控页面或环境，显示起点、输入、profile；明确哪些登录状态被复用。profile 不等于完整内存状态。

补齐后退、前进、刷新、地址导航和标签操作；实时页和历史回放必须有明显标识。进入回放时隐藏而不是销毁 live WebContentsView，退出后恢复其原来的页面。脚本并行任务默认分配不同页面，同 profile 共享 Cookie 等事实应写进隔离说明，不能声称不同标签就是完整隔离。

停止/取消通道优先，不被无关的全局 busy 阻断；主进程仍执行状态校验。已经实现的页面 generation、控制租约与原始错误保护不能因拆模块丢失。

**验收：**停止录制后页面、输入和未提交现场仍在；开始第二段录制不导航；关闭页是显式操作；两种执行模式在记录与界面均可区分；一个历史窗口的读取不改变实时页选择。

## 5. 连续录制、持久化与缺口（T02）

### 5.1 录制主线

rrweb 已提供完整快照、增量事件和周期 checkout；它不是视频编码器，也不是原站脚本重执行器。[R5] 用适配层封装录制与回放依赖，锁定确实验证的 recorder/replayer 组合。官方目前建议 `@rrweb/record` / `@rrweb/replay`，但包迁移需要验证分发文件、导出路径和旧录制读取，不能仅改 import。[R5]

每个 page/document/frame 建立明确事件流；保留每流源序号、采集时间、host 接收序号和时钟映射。不把跨进程到达顺序当作严格因果顺序。录制主时间轴呈现用户当时的标签切换，页面状态独立还原；初始化、导航、断连和重新注入都是明确边界。

周期 full snapshot 是技术还原起点，不是业务 checkpoint。间隔根据事件量、DOM 大小和随机定位测量配置，不用一个未经测量的固定值当作最佳实践。完整快照必须与源属性补充基线、frame 映射和资源清单关联。

### 5.2 不把高频数据全部塞入同一丢弃队列

对采集通道建立优先级与预算：结构性 DOM 变化、初始化、导航、显式 checkpoint 和缺口记录优先；鼠标轨迹等可以按明确策略采样；网络正文与大资源单独限额。

预算同时考虑排队条数、排队字节、正在处理的实际大对象和持久化速度。不能用固定 4 KiB 估值声称限制了实际数 MiB 的正文。达到上限要背压或明确降级，不无限增加内存。

一旦结构性事件或源元数据丢失，记录受影响 stream、事件区间、类别与原因；请求新的完整快照建立恢复起点。新快照不能抹去旧缺口。区间缺口的开始可取最后确认可靠位置，结束取重新建立一致基线的位置，无法确定精确丢失时刻时如实扩大范围。保留资源缺失、结构缺失、元数据缺失、采样与隐私遮罩的不同类别。

### 5.3 写入与崩溃恢复

复核现有 writer 修复，在保持单写者和耐久性语义的前提下采用批处理/group commit；显式 checkpoint、封存、版本发布等待 flush barrier。用户界面区分“采集中、已入队、已耐久保存”；不要先告诉用户保存成功，崩溃后才发现尚未落盘。

分段文件保存长度、校验和、事件起止及 full snapshot 索引。索引可由原件重建；截断尾部不丢弃此前有效段。Windows 原子替换、占用与短暂失败需有界处理，不无限重试。被确认保存的原件在强杀、磁盘满和重开后必须可核验。

将高频序列化、压缩、索引等工作逐步移至 worker；Electron 主进程保留必要的生命周期与浏览器控制。迁移按实测热点进行，不先引入多个服务。

**验收：**结构事件缺口可定位；full snapshot 后可靠性恢复；降采样鼠标不被误报成 DOM 丢失；晚到任务不修改已封存材料；强杀后能读回已确认数据；内存/队列按进程与通道记录，不只给总 PASS。

## 6. 离线资源归档（T03）

**意图：历史回放不依赖原站仍在线，也不从现在的网络内容补造过去。**

rrweb 当前官方说明 `captureAssets` 尚不会自动保存资源字节；样式内联和 `inlineImages` 不能替代完整归档。[R6] 新模块独立于常规“供 Agent 分析的网络正文预算”，但复用已捕获响应与字节，避免重复抓取。

### 6.1 资源捕获与身份

在录制期间获取实际使用的 CSS、图片、字体、相关 SVG 和资源依赖。优先利用已有 CDP/浏览器采集链路；验证缓存、重定向、Service Worker、blob/data URL、跨源资源与 frame 覆盖。不得为获取资源普遍开启会阻塞站点的网络拦截，也不得在后台访问用户未授权的资源。

资源身份包含来源 recording/page/frame/request、采集时刻、MIME、原始 URL、响应/解码信息和内容 hash。相同 URL 不代表相同内容；内容相同可共享 blob，但原始来源关系保留。资源状态至少区分：`captured / late-fetched / missing / redacted / unsupported / failed`。后来补取只能作为额外材料，不能顶替当时原件。

### 6.2 回放引用

用 CSS/HTML 解析工具处理 URL 和依赖，不用全局正则替换所有字符串；考虑相对路径、`baseURI`、`@import`、`url()`、`srcset`、字体和内嵌 SVG。原始 URL 保存于源信息，回放 URL 单独生成，不能污染 selector 生成。

资源访问通过专用只读协议或受控资源服务，按归档 manifest 解析 blob，禁止任意文件路径、越界、符号链接逃逸和访问当前 profile。MIME/内容风险、响应头、外部嵌套引用和网络 egress 均需测试。对动态样式、CSSOM、adoptedStyleSheets、字体加载等逐项验证采集与恢复，不以“HTML 里有 style”宣称全部覆盖。

### 6.3 体积、隐私与完整性

配置单资源和总归档预算，超限明确记录；网络 Cookie、Authorization、一次性 token、敏感输入和源属性补充遵循同一隐私规则。完整性报告按 DOM、源属性、样式、图片、字体、frame、Canvas/媒体分类；不把只保存截图称为 DOM 还原。

**验收：**重启应用、关闭原站并断网后目标页面可还原；阻断全部外部请求时仍能读取已归档资源；同 URL 不同内容恢复正确版本；缺失资源不会静默联网；原始属性不出现归档协议地址。

## 7. 时间轴回放、随机定位与安全（T04）

### 7.1 基础交互

使用 rrweb `Replayer` 与自己的 React 存档界面，现成 rrweb-player 可用于原型验证。核心播放器接口已有暂停、指定偏移播放等能力；异步 `addEvent()` 不等于自动具备有界内存随机访问。[R5][R7]

实现播放/暂停、倍速、拖动、原始时间显示、跳过空闲、前后 checkpoint、页面轨道/标签、导航标记和缺口区间。checkpoint 的 anchor 固定到原始时间与事件序号；切换倍速、跳过空闲、缩放时间轴均不能改变 anchor。

### 7.2 随机定位流程

```text
用户选择原始时间
→ 映射到 page/document/stream 与事件边界
→ 查询此前可靠 full snapshot 及源信息基线
→ 加载必要分段与资源映射
→ 重建并应用至目标事件
→ 等待必要资源/样式及有界布局稳定检查
→ 验证当前 seek 请求身份
→ 发布可检查状态，允许创建或编辑 checkpoint
```

每次 seek 带递增请求代际和取消信号；旧 seek 的资源、DOM 或镜像结果不能覆盖新位置。远距离跳转可以销毁旧 replayer 并重建，有界缓存邻近段；释放 event 数组、Mirror、iframe、object URL、监听器、定时器与 worker 引用。

“重建完成”必须有可观察条件，而不是固定 sleep。重建 UI 展示 loading/degraded，不能在节点尚未稳定时接受绑定。

### 7.3 布局还原

保存原 viewport、设备缩放、页面缩放、滚动和相关显示环境。回放先按原尺寸布局，再整体缩放到工作区；侧栏拖动不能重触发历史网页的响应式布局。显示当时截图作为视觉参照，但截图与 DOM 本非原子捕获时保留时间范围与一致性说明。

暂停后为查看已存在 DOM 的辅助滚动属于阅读操作，不伪造原始事件；checkpoint 仍指向原历史位置。若输出阅读态截图，应标明为派生视图，不冒充当时截图。

### 7.4 安全边界

回放环境不运行原站业务脚本、不使用当前 Cookie、不提交表单、不导航原站、不发起外部请求。保留 sandbox/contextIsolation，不为了 Canvas 或选择方便直接启用会解除脚本隔离的选项；rrweb 文档对 `UNSAFE_replayCanvas` 明确存在这类风险，特殊内容另定受控方案。[R5]

需要检查回放节点时，应在可控回放壳与只读桥接内完成。若 sandbox origin 限制使父层不能直接读取 frame DOM，设计经校验的内部选择消息桥；不要临时给归档内容 Node 能力或任意宿主 IPC。单凭隐藏 `<script>` 不是隔离方案。[R8]

**验收：**顺序播放与直接 seek 到同一事件的关键 DOM/字段一致；旧 seek 结果不覆盖新状态；长录制多次跳转内存趋于受控；错误区间不显示完整可信；历史页选择不触发真实网站行为。

## 8. 原始 DOM 信息、历史节点与 CSS/XPath（T05）

### 8.1 三层职责，不能混成一个 selector 字段

1. **历史节点身份**：这段录制这个时刻的哪个节点；使用完整作用域的 Mirror ID。
2. **原始元素信息**：当时的原始 attributes、文本、结构与约定的 properties。
3. **原站定位器**：Agent 以后如何寻找该语义对象；候选 CSS/XPath/分段 frame-shadow 路径，必须独立验证。

selector/XPath 不是元素自带的唯一属性；它们是对某一查询作用域生成的表达式。DOM 中唯一命中不代表下一次实站仍可用。

### 8.2 已有能力与必须复核的转换

前轮对 rrweb 2.1.6 的源码调研指出：`serializeElementNode()` 遍历元素属性，mutation 流记录增删改；`Replayer.getMirror()`、`Mirror.getId/getNode()` 支持回放节点与历史 ID 映射。与此同时，URL 绝对化、link/style 转换、script/noscript 映射、表单状态序列化、事件属性与隐私过滤可能改变回放 DOM 的原始语义。实施时逐一对照以下源码，而不是把说明当作全部已覆盖：[R9]

```text
packages/rrweb-snapshot/src/snapshot.ts
packages/rrweb-snapshot/src/rebuild.ts
packages/rrweb-snapshot/src/utils.ts
packages/rrweb/src/record/mutation.ts
packages/rrweb/src/record/index.ts
packages/rrweb/src/record/iframe-manager.ts
packages/rrweb/src/record/shadow-dom-manager.ts
packages/rrweb/src/replay/index.ts
```

典型反例：原页面 `<a href="/orders/42">` 在回放中成为绝对 URL，从回放生成 `a[href="https://…/orders/42"]` 不一定能匹配原页面的原始 attribute。也不能把绝对地址一律改成相对地址来反推原文。

### 8.3 原始信息补充层

复用 rrweb 的结构和普通属性，补存被改写/合并的信息，不开发第二个完整 DOM recorder。字段至少包括：原始 attributes 的存在/删除/空字符串区别，必要 `value/checked/selected` properties，命名空间、文档 URL 与 baseURI、frame/shadow 边界，以及源序号。原始 attribute 与运行时 property 分开；不保存所有 JavaScript 属性、事件闭包或框架内部对象。

补充时机覆盖 full snapshot、新节点、属性更新、表单状态变化和文档/镜像重建；不能只录首次快照。隐私遮罩与 rrweb/网络证据一致，禁止借元数据旁路保存被遮罩明文。

优先使用可验证的插件、Mirror 和事件处理扩展点。但若插件发射时转换已不可逆，或回读实时 DOM 无法与事件批次一致，则在序列化和属性 mutation 处加窄范围原始信息 hook，锁定补丁、写测试并保留上游化说明。不得在项目各处直接依赖 rrweb 私有字段。

对跨源 iframe，特别验证自定义 plugin payload 的 nodeId 是否经过与内建事件相同的变换；不假设 rrweb 会自动改写任意 payload。以 frame/source epoch 记录身份，或在明确的转换阶段统一 ID。metadata 与 DOM 流不同步时标记 metadata gap，不伪装原始值已恢复。

### 8.4 历史源结构与定位器生成

通过 full snapshot + 增量 + 源信息还原指定时刻的**源结构模型**。模型保留原始 tag、attributes 和顺序；回放辅助节点、改写后的 URL 和布局样式不进入定位器基础。可复用现有树模型或受限的惰性文档，防止生成模型时执行脚本或联网。

用户选中回放元素后通过 Mirror 取得身份，再查询对应源节点。只在选择时生成定位器，不持续为所有节点计算路径。候选优先考虑稳定 ID、`data-*`、`name`、语义属性、稳定容器与实体关系；动态 class 和 `nth-child` 标记脆弱性，不编造可靠度概率。

CSS、XPath 的转义、重复 ID、Unicode、引号、SVG 命名空间、同类兄弟节点均需测试。可参考 Chromium DevTools `DOMPath.ts`，但需适配其节点模型并保留对应许可说明，不直接假设它是独立 npm 包。[R10]

跨 iframe 或 shadow root 输出结构化分段定位计划；普通 CSS/XPath 不假装跨越所有文档/根。开放 Shadow DOM 在实际录制支持范围内实现；closed Shadow DOM 未验证前显式 unsupported。Canvas 内绘制内容用不同的 `visual-region` 引用，不能伪装 DOM 节点。

### 8.5 验证和交付状态

每个候选记录表达式、查询作用域、生成依据、历史命中数、是否命中目标、依赖顺序/动态属性的提示和验证位置。状态至少区分：`historical-unique / historical-ambiguous / invalid / live-verified / live-failed / not-live-checked`，必要时拆成多个字段，不能互相覆盖。

源结构模型上的历史验证、独立保留的源页面测试、授权后的实站验证是不同层级。不能在回放 DOM 里生成再在同一回放 DOM 验证，就声称原站可用。原站验证必须携带 page/document 身份，默认只读，不能自动访问真实账号完成此测试。

**验收：**相对 URL、表单 property、标签转换、动态属性、列表节点复用、frame ID、seek 重建均不导致错绑；元数据缺失时明确显示不能生成可靠原始定位器；没有真实复跑就不显示 live-verified。

## 9. checkpoint、普通注释与需求字段交互（T07、T08）

### 9.1 存档后创建、修改与复制

用户可以在完整录制区间任意暂停，新增 checkpoint，无需当时按过保存。保存 anchor 与来源关系；在缺口区间允许保存文字观察/疑点标记，但不可创建“已精确绑定可靠 DOM”的假记录。原始材料不完整时，应说明补录能取得新证据，不能恢复未保存的过去。

修改已有卡片进入资料草稿；复制卡片引用同一历史时刻并复制可独立编辑的注释。卡片创建时间、原采集时间和显示顺序分开。后来补录是新 recording，可纳入新资料版本，不能插入并伪装为原始时间线上的事件。

移动 checkpoint 的历史时间必须重新验证全部元素绑定；失败的绑定保留为待重绑，不静默删掉，也不凭相同 nodeId 判定仍正确。派生快照/缩略图作为缓存，写明源位置、生成时间及回放器版本；不对回放 iframe 的 `outerHTML` 二次保存冒充原件。

### 9.2 普通元素注释

```text
checkpoint 行“注释”
→ 自动打开该 anchor 的历史回放并暂停
→ 创建 SelectionSession
→ 悬停高亮、点击选择
→ 展示节点摘要和注释框
→ 保存到当前资料草稿
→ 退出检查，回到此前工作状态
```

`SelectionSession` 明确 project/draft/checkpoint/anchor、用途及可选 fieldId，并保存请求代际。选中节点的文本、角色、原始属性摘要和位置可预览，但默认不显示整段 JSON。

一张 checkpoint 可有多条注释；多目标注释可在基础单目标稳定后扩展，模型不得强制一张卡片只有一个全局 selection。保存普通注释要求有内容；单纯字段绑定可以没有附加注释。

### 9.3 检查模式与蒙版

删除独立“元素”tab，把入口放到 checkpoint 注释、字段绑定、已有绑定的查看/重新选择。进入检查后，对其他无关界面加蒙版；应用状态层同时阻止冲突快捷键、菜单、导航和提交，不能只加 CSS 遮罩。

保留注释输入、保存、取消、Esc 与紧急停止。点击事件必须在实际触发网站动作前被拦截，覆盖 pointerdown/mousedown/click、链接、表单、键盘与焦点边界；优先使用离线回放只读选择层，不能直接把 `enableInteract()` 当作检查器。[R11]

Electron 原生 WebContentsView 与 React DOM 的层级不同；主方案是在原浏览器区域切换到自有回放壳并隐藏 live view。跨进程只读选择桥、坐标变换、DPI、缩放、iframe、Shadow DOM 命中都需实测。历史标注只锁当前编辑/选择会话，不阻止 Agent 读取别的已发布资料。[R12]

### 9.4 需求 checkpoint 与字段

“需求”是 checkpoint 的编辑视图，不是需求唯一归属。字段最小必须有名称/明确含义；类型、单位、空值、遮罩值与转换要求逐步填写，有歧义给提示而非伪造默认业务答案。

必须支持三个路径：仅字段说明；字段 + 元素；字段 + 元素 + 注释。元素绑定默认表示字段语义和样例，不强制最终脚本从 DOM 提取。只有显式的“必须按页面显示值/限定来源”才约束数据来源。

字段属于数据集/实体，例如 `orders.paid_amount`；允许绑定重复项容器，说明样例属于哪条实体。分页范围、筛选条件、全量/增量、主键、去重、列表详情关联和遮罩处理是独立要求，不靠点一个金额元素自动推断。样例值不是固定验收常量。

**验收：**旧 checkpoint 注释永远作用于旧历史页而非当前实时页；取消不残留；复制后互不污染；字段不绑定元素也可保存；绑定后不写注释可保存；同需求多卡片引用不会产生无意重复定义。

## 10. 脚本模块化、错误隔离与部分结果（T09、T10）

### 10.1 意图与保留边界

目标是独立任务不互相拖死，不是“捕获全部异常然后假装继续成功”。保留普通 Node/TypeScript/Puppeteer 代码，辅助执行器只是可随业务项目交付的轻量 helper；不根据 checkpoint 自动生成执行步骤，不把分支循环再写进 JSON DSL，不引入 Studio 专属 Page 抽象。

推荐按业务依赖拆函数：检查登录 → 订单列表 → 每笔订单详情；账号资料是列表的独立兄弟模块。账号昵称失败不阻止订单列表；列表没有取得订单 ID，详情明确 blocked。某笔详情失败不影响其他已知 ID 的详情。

### 10.2 统一步骤包装

在现有 runner 周围补少量普通代码约定，覆盖：步骤/实体身份、前置产物、开始结束、超时、取消、有限重试、日志、证据采集、产物提交和清理。业务模块只声明自己的输入/输出与前置检查；是否并行由显式安全边界决定，而不是所有模块默认 Promise.all。

示意，不作为必须照抄的 SDK：

```ts
const orders = await runStep('orders.list', {
  signal,
  retry: { maxAttempts: 2, policy: 'read-only' },
  run: ctx => collectOrders(ctx.page, input, ctx.signal),
});

await runIndependent('account.profile', collectProfile);
if (orders.status === 'succeeded') {
  await runItems('orders.details', orders.value.ids, collectOrderDetail);
} else {
  recordBlocked('orders.details', orders.attemptId);
}
```

正式实现需要显式 Result 联合类型、错误原因和依赖身份，不能用 `any` 加字符串拼接规避类型契约。

### 10.3 失败分类

| 情况 | 正确处理 |
|---|---|
| 某实体详情读取失败 | 保留错误及该实体身份，继续其他独立实体 |
| 辅助截图失败、数据已取得 | 保存数据，记录证据降级；依赖截图的检查为 inconclusive |
| 前置列表失败 | 依赖它的详情 blocked，不无输入盲跑 |
| 登录失效或需验证码 | 暂停相关范围，请求真正人工操作；无回复不等于成功 |
| 用户停止 | 传播取消，确认自动化静默，不启动后续任务 |
| 磁盘不可写、数据无法持久保存 | 停止受影响执行，保留诊断，不能继续丢数据 |
| worker 已崩溃/状态不明 | 明确失败/未知，不凭剩余日志推定完成 |
| 非幂等外部操作超时 | 默认不自动重试，结果不明单独报告 |

状态应能表达 `succeeded / partial / failed / blocked / cancelled / awaiting-human`，执行状态与证据质量分别记录。原始异常、栈和原因优先于后续 transport 清理错误。

### 10.4 真正取消，不是 Promise 超时后放任后台继续

`Promise.race` 超时不代表浏览器操作已经停止。取消信号必须贯穿排队、启动、步骤、证据收集和持久化边界；阻止新命令后，对已发命令按可验证方式收敛，必要时关闭该步骤拥有的页面或终止其 worker。确认静默之前不把页面交还用户并声称自动化停止。

同一页面不并发运行多个会导航/写入的步骤；每步拥有的页面、连接和临时文件可独立清理。不同页面仍可能共享 profile 状态，敏感操作需要额外串行或独立环境。

### 10.5 可重跑，但不从历史 DOM “继续运行”

支持指定失败模块或实体重跑。恢复前检查登录、输入、前置产物和代码/资料兼容性；历史快照不是可执行浏览器断点。每次重跑形成新 attempt，引用旧产物时记录来源及有效性检查；时间敏感数据不能默认永久复用。

聚合多次尝试的结果可展示，但要保留每条数据的来源 attempt；不得伪装成一次连续全通过的执行。自动重试只对明确只读或幂等步骤启用，并限制次数、退避和总预算。

### 10.6 增量数据输出（T10）

扩展现有 reporter，支持数据集按批追加、最终完成标记和失败时保留已提交部分。实现可采用 `beginDataset → appendBatch → finishDataset` 语义，单次 `emitData` 可通过兼容适配调用，不必立即破坏现有示例。

每批含 execution/attempt/step/dataset、batchId、实体主键及 schema；重复批次有幂等处理。明确允许 append、按主键更新还是拒绝重复，不能把后到重复静默覆盖。每批持久化后返回提交状态，最终报告保存摘要和文件引用，而不是在主进程、worker 和 UI 各保留一份全部数据。

结果查询分页/投影；区分真实空数据、尚未完成、读取失败、被截断和缺失字段。UI 支持主键检索、失败实体筛选、来源跳转和导出。数据集 `complete` 只有明确完成条件与证据支撑时成立，不由进程正常退出自动推导。

**验收：**人为使 profile 模块失败仍可取得订单；一笔详情失败不丢其他数据；截图失败不吞业务数据；取消后无迟到点击；强杀重开能读取已提交批次；从失败点重跑不重复污染结果。

## 11. 需求验收与结果中心（T11）

### 11.1 验收绑定不可变目标

执行必须绑定用户确认或明确标为候选的资料版本、代码指纹、输入指纹与环境记录。业务脚本的 `workflow.json` 可以声明实现覆盖和输出契约，但不能独自定义/删掉用户需求。

运行前冻结实际要执行的代码和依赖身份，防止计算 hash 后目录被修改、后续动态 import 执行了另一份代码。推荐建立受控执行快照或经过验证的同等机制；Node 运行目录限制本身不是完整文件/网络沙箱。

### 11.2 判断分层

结果分别展示：格式/schema 通过、来源引用存在、来源内容约束已验证、脚本自行报告、人工确认、证据不足。一个真实存在的 artifact ID 不能证明字段取自它；脚本上报 `complete: true` 和 `terminalReason: done` 不能独立证明翻完所有页。

先强化关键字段与完整性要求，不对每一个字符建立昂贵血缘系统。关键来源引用包含实体主键/字段、artifact/request/历史节点、JSON Pointer 或 DOM 位置、采集时刻、转换说明和对应版本。分页终止应有末页状态、游标结束、总量或其他任务特定依据。缺失或矛盾材料保留 `inconclusive`。

输出字段绑定默认是语义样例，因此允许 Agent 改用语义一致的网络数据来源。需要按显示值交付或保留遮罩的字段，显式检查该要求，不能擅自补全隐私信息。

### 11.3 UI 以结果为主

默认显示数据、覆盖范围、失败/缺口和下一步；展开后才看原始事件与 JSON。按需求关联示范、执行材料和结果，不靠同名字符串或 React 临时 state 推测基线。长 checkpoint/事件/材料列表均有界续读，用户不必转去 API 才能看后半段。

人工评审独立追加，包含接受/拒绝/例外、理由和范围，不覆盖机器报告。Agent 的建议评审不能标为人工结论。

**验收：**删除脚本中的 requirement 不会缩小用户目标；伪造“第一页已 complete”不能独立通过全量分页要求；来源 ID 存在但内容无关时不能声称内容已核验；V1 结果不自动成为 V2 通过；部分数据明确呈现而非全部失败或全部成功。

## 12. Agent 权限与接口（T12）

### 12.1 分开三个概念

**权限**决定能不能做；**互斥控制**决定现在谁能操作这张页面；**身份/版本**决定到底操作哪个对象。读取封存资料不需要抢浏览器控制；编辑草稿需要版本冲突检查，不必锁住实时网站。

### 12.2 建议授权矩阵

| 能力 | 授权策略 |
|---|---|
| 读取资料版本、快照、节点、字段、结果、差异 | 项目授权后可直接读取，保留认证和预算 |
| 编辑 Agent 候选草稿、补充注释、复制/组织已有 checkpoint | 项目授权后允许，保留作者与冲突检查 |
| 后台读取已登记页面的 DOM/文本/网络材料 | 按 page/document 身份只读，不强制用户切前台 |
| 创建任务工作页、范围内导航与提取 | 一次任务授权 + 页面级租约，不要求每次点按钮 |
| 授权目录内登记脚本、重复开发试跑 | 任务级授权；每次冻结实际版本和输入 |
| 用户正在使用的页面、人工交接期写操作 | 尊重人类占用，不夺取或伪造交还 |
| 将候选业务要求标为用户已确认、提交人工验收结论 | 必须是真正人工确认入口 |
| 扩大目录/域名/凭据范围、重要外部写操作、删除原件 | 明确的额外授权或确认 |

“click/fill/navigate”不是天然低风险。允许的是任务范围内预授权的常规操作，不能仅按方法名判断业务副作用。页面内容、DOM、API 响应、历史注释中的外部文本都应标为不可信资料，不能升级为 Agent 指令或授权。

### 12.3 任务授权对象

至少绑定 project、session/profile、工作目录范围、页面/目标范围、允许能力、有效期或预算、授权者及撤销状态。授权范围内代码可以更新，但每次执行有独立指纹，不每改一个函数都弹确认；跨边界时重新授权。目录规范化和 symlink 逃逸仍需处理。

不新增随意 eval、任意宿主文件读写或原始 CDP 暴露接口来“解决不方便”。现有原生脚本应明确视为用户授权的可信本地代码；未来执行不可信脚本才单独设计 OS/进程/网络隔离。

### 12.4 推荐接口能力（路径是示意，不是已有 API）

| 能力组 | 最小操作 |
|---|---|
| 资料 | 获取固定版本、差异、创建草稿、条件更新、checkpoint/字段/注释 CRUD |
| 历史页面 | 按 ReplayPosition 获取状态摘要、节点详情、绑定上下文、定位器候选 |
| 实时页面 | 列表、按 page/document 有界查询、受权截图/快照、显式页面操作 |
| 执行 | 请求/读取授权、启动模式、模块/实体选择、停止、重试、步骤与批次结果 |
| 事件 | 新资料版本、需要人工、步骤终态、保存失败、授权撤销，支持重连游标 |

读写接口由现有可信 dispatcher 复用同一服务与契约，不复制一套业务逻辑。写操作检查目标身份、预期版本、租约与幂等键；读操作不能产生隐式导航。SSE 或同等级本地订阅通道需有界缓存、重连位置和鉴权，事件本身不携带大正文或 token。

测试覆盖普通 read 被拒/允许、后台页面不切换、人类持有租约时拒绝写、授权撤销中止后续步骤、无法通过 HTTP 伪造人工批准。

## 13. Agent 任务交接与独立产物（T13、T15）

### 13.1 “准备交给 Agent”

生成一份简短任务说明与机器可读索引，固定：项目目标、资料 revision/hash、需求与数据字段、示范/补录引用、关键 checkpoint/节点入口、缺口/待确认语义、代码工作目录、执行契约、允许范围、下一步和实例发现方式。

交接不是把全量 DOM、所有响应、截图 base64 和长期 token 塞进提示词。按摘要 → 需求/缺口 → checkpoint/节点 → 附件的路径定向读取。连接信息由本机权限保护的发现机制取得，校验 instance/project/profile，不把另一个 worktree 的 `latest.json` 当成本实例。

新 Agent 不需要先读整份历史进度才能做任务。资料变化用 revision diff 接续；已经实现的代码要声明针对哪份资料，未通过的要求要有明确列表。

### 13.2 应用交付与业务脚本交付分开

应用安装包必须带齐需要的 worker、回放样式/脚本、资源处理器、运行契约和可导出的 skill/任务说明。不可依赖开发仓库中的文件偶然存在，不能全局自动安装技能。

业务产物包含自己的依赖、入口、输入 schema、输出说明、错误/部分结果语义及必要的便携 helper。用普通 Puppeteer；Studio 的 reporter/evidence adapter 可选，不应关闭 Studio 就完全无法执行。不要为了便利复制真实录制、Cookie、profile 或账号信息到业务项目/Git。

**验收：**安装版可创建交接材料；新 Agent 定位正确固定版本并提交验证；业务项目复制到独立目录后按自身说明安装并运行，不访问 Studio 内部源码；缺少人工登录时明确等待，而不是假装独立测试通过。

## 14. 工程分层与文件所有权

按职责拆分，而不是按文件行数机械拆。保持单包，不把每个名字都实现成独立进程。

| 现有入口/领域 | 建议职责边界 | 实施注意 |
|---|---|---|
| `src/main` 中的 Studio、页面与调度 | session 生命周期、应用编排、可信 IPC/HTTP | 不把所有新逻辑继续塞回 Studio |
| `src/capture` | recorder、源信息 hook、采集通道与健康 | 统一节点/事件身份，唯一注入入口 |

| `src/contracts`、`src/shared` | 少量共享类型与 schema | T00 指定唯一 owner；其他会话提变更请求 |
| 新资料领域模块（路径由 T00 定） | draft、revision、requirement、checkpoint 注释 | 不依赖 renderer 临时状态 |
| `src/runner` | 轻量步骤包装、取消、attempt、批次输出 | 普通 Puppeteer 仍是业务 API |
| `src/renderer` | 工作区/存档阅读状态、时间轴、选择、字段、结果 | 当前运行与选中历史资料分开，只有一个集成写入 owner |
| `src/preload` | 有类型且最小化的桥接 | 不把任意 Node 能力交给回放内容 |
| `test`、`examples`、`skills` | 合成回归、独立示例、交接入口 | 按真实源码边界复用已有测试入口 |

共享文件和锁文件由 S0/G 集成 owner 管理。子会话优先新增边界内模块；需要改主入口或契约时提交小型补丁/变更请求，避免多人同时大改 `app.tsx`、Studio、dispatcher、package.json 和 lockfile。

| AT40 | 安装包与独立业务目录分别跑通；回放资源/worker/skill 不依赖开发目录 |

真实账号、验证码或站点权限需要人工时，先完成合成站点全闭环，最后记录人工场景验证；未能执行真实场景要标未测，不以合成测试代替。截图对照只作为视觉证据的一部分，不能证明源属性一致。

性能阈值由 T00 在固定硬件/fixture 上记录并冻结：至少包含录制开销、磁盘吞吐、队列峰值、seek 分位耗时、主进程/页面/回放 worker 内存与增长趋势。不能用“更流畅”代替测量，也不预先伪造一个通用零增长上限。

## 17. 发布、旧存档与风险处理

### 17.1 渐进迁移，不破坏已有材料

通过 feature flag 或格式能力检查逐步启用新录制与回放；旧材料只读导入/投影到资料版本，不原地重写。已有完整事件可以重建；当时没录到的 DOM、资源或源属性必须标缺失，不靠现在重新访问补成历史事实。

当前仓库不要求兼容所有历史开发格式；本次只需要对实际存在且需要保留的档案制定显式迁移/只读策略，不开发无限兼容层。迁移测试用合成拷贝，禁止把真实录制或 profile 放 Git。保存升级前备份并核对 hash。

### 17.2 关键技术门槛

先完成 T00 的小型贯通验证：相对 URL + 动态属性 + 表单状态 + 后期节点选择 + 反复 seek；确认源信息和节点映射路径后再扩大 UI。如果当前插件不能可靠提供转换前信息，采用窄 hook；若某类页面无法覆盖，写 capability report，而不是删除用户的核心还原要求。

安全回放和资源归档不允许以“先开放所有脚本/网络以后再收紧”实现。模块隔离也不能通过吞掉异常、降低验收标准或抹去已有失败证据完成。

### 17.3 完成报告

每个工作包提供代码 commit、影响文件、真实命令/结果、AT 覆盖、格式/API 变更、限制和后续接续点。主集成维护 `docs/refactor-status.md`，状态使用 `not-started / implementing / verified / blocked`；“代码已写”不等于 verified。

最终用户可操作闭环：自然示范 → 停止录制不关页面 → 断网重开存档 → 拖动至后来选定时刻 → 新增需求 checkpoint → 绑定字段且可不写注释 → 修改/复制形成 V2 → 新 Agent 读取固定 V2 → 运行独立模块且保留部分失败 → 查看数据与来源 → 修复重跑 → 独立脚本交付。

### 17.4 工作量口径

前轮给出的 3–5 人日原型、16–27 人日普通 DOM 绑定可用版、34–60 人日包含资源归档/长录制/更多页面边界的估算，是按熟悉技术栈工程师的人工作量粗估，且后两档含前面工作，不应相加。它们不包含本文全部 session、权限、执行器、结果中心与集成重构，也不是 Codex 时间/费用保证。

本次更适合按依赖、风险、AT 验收与实际 token/修复返工记录管理。并行降低部分关键路径，不意味着所有模块可以同时修改，也不意味着人日线性折算成 Agent 用时。
