### 本轮必须交付

1. 保存点工作区不再包含草稿列表、固定版本列表和“发布候选版本”；主要动作明确指向保存点。
2. “存档”统一承载资料版本、来源录制与工作副本管理，但三者有不同语义；固定版只读、编辑副本明确。

4. 项目、环境、工作副本和存档的管理闭环；不能仅有创建和一个无法改变任何属性的“管理”弹窗。
5. 补足日常内置浏览器基础操作，并保护录制/执行/原生视图身份。

### 1.3 本次新增的具体代码检查

**版本号和列表：** listSummaries在目录内选择字典序最小的一页ID；前端只排序这页，再给它标V号。最新版本可能在后页，加载更多会使已看到版本改名。因此换一个UI位置不能解决底层问题。[S03][S06]

**taskBrief差异：** materialContentHash包含taskBrief，differences仅遍历requirements/fields/checkpoints/annotations和recordingRefs。只改变objective/scope可以得到不同内容hash，却没有对应diff条目。这里应补真实服务回归，不能用“hash变了”代替人可理解的变更。[S06][S12]

**保存后的旧对象回填：** selectCard(item)在changeEditor保存后仍用原回调里的item.title等设置表单。需要检查“修改标题后重点击同卡/切回卡片”是否重装旧值。修法是传ID并从保存后的实体状态取值，不再拼更多延时；这条是源码可达风险，本次未实跑React。[S03]

**失败内存状态：** 对workspace.json写入失败注入测试，验证项目或环境不存在/旧内容保持，不能刷新页面就看到“失败的新建”。重试按operationId而非再生成第二个对象。环境初始化同理，不能用window.lock(false)假装回滚。[S09]

## 2. 先把名词与归属定清楚

### 2.1 用户只需理解四件事

| 用户看到 | 含义 | 技术映射 |
|---|---|---|
| 项目 | 一项持续整理、实现和验收的业务任务 | 现有Project，仍不额外新建多层Workspace/Collection体系 |
| 保存点 | 某个网页时刻值得说明的内容，可有字段和注释 | 当前资料中的CheckpointCard，引用不可变来源 |
| 当前工作副本 | 尚可编辑的整份任务资料，不是一条保存点 | TaskMaterialDraft；默认自动准备一个 |
| 存档版本 | 固定的一份任务资料，执行/交接按它核对 | TaskMaterialRevision和hash；内容不改 |

“原始录制”是证明页面当时如何变化的连续材料，在存档里可查。它不是工作副本、也不是资料版本。一个资料版本可以引用多次录制；一次录制可被多个资料版本引用。

**把版本管理放进存档是正确的，但不要因此强迫每个录制run各拥有一套需求。** 本轮不引入新的独立Archive聚合ID；“存档”先是项目下已有资料版本和原始录制的统一导航与关系视图。

### 2.2 三类“保存”不能混用

- **记录当前页面 / 在此时刻添加保存点**：取得或引用一个可靠源位置，创建一张卡片；不新建工作副本或固定版本。
- **保存修改**：将当前字段/注释/卡片改动写入工作副本；不封存实时浏览器、不新建原件。
- **保存存档版本**：冻结工作副本的一致快照；不意味着验收通过、人工接受或发布到互联网。

“结束录制”只结束原始采集段；浏览器保留。不要将“结束录制”“保存修改”“保存存档版本”“交给Agent”做成一个隐式连锁动作。

若固定版本需要可封存的来源而当前录制仍在进行：保存草稿照常允许。存档对话框列出影响，提供“结束这段录制并保存版本（保留页面）”或返回继续编辑；不要后台偷偷封存。只有真实实现了原件耐久水位绑定，才能再提供“固定当前已记录范围但继续录制”的选项。旧合法资料仍按其原身份读取，不能为新UI重写其内容。

### 2.3 “候选”不应占据普通主操作文案

普通用户用“保存存档版本”或“固定资料版本”。人/Agent作者、候选建议、是否被确认以及执行结果仍保存并可查看；它们不是同一个状态。Agent编辑的候选不覆盖用户的工作副本或“当前接受版本”。

存档版本Vn是稳定展示编号，revisionId/hash才是机器身份。工作副本rN是并发修订，不再放在保存点旁让用户误认为卡片版本。

## 3. 目标界面结构

具体行为见14，本节规定职责而不是强制像素。

### 3.1 主区域

- **保存点工作区（默认）**：保存点列表、选中卡片摘要、字段/注释局部编辑、实时或历史浏览器。
- **存档**：资料版本 / 原始录制 / 工作副本三个明确子视图。版本创建、比较、基于旧版编辑、工作副本命名与处置都在这里。
- **实现与结果**：代码目录、实现映射、输入、固定版本执行和结果。普通参数能由已登记schema表达时提供表单，JSON为高级入口。
- **项目与环境管理**：专门管理页/面板，名称与实际功能一致；“连接信息”另放设置/诊断，不能继续叫“连接与环境”却只列地址。

项目、当前会话环境/控制者、是否录制、编辑工作副本/只读版本这些上下文始终清楚。UI正在浏览项目B，实时session仍属于A时显示明确横幅，不能将A现场存进B；允许只读浏览B，不要求先关闭A才能看历史。真正打开B的环境才走显式切换/关闭流程。首版仍可只开一个实时session，不需为浏览目录实现多实例。

### 3.2 默认保存点页的动作预算

持续显示：**新增保存点、添加字段、添加注释**和列表搜索/筛选。保存dirty状态只用一处“保存修改”和快捷键；复制、移动历史位置、移除放在卡片更多菜单。无选中卡时字段/注释动作显示简短前置而不是无限空表单。

选中卡片默认显示标题、来源页面/时间、说明、字段摘要行和注释摘要行；点某项才展开其一个编辑器。技术JSON、节点ID、sourceProof和定位器放“查看来源/高级”，不长期占据主区域。

默认不要同时显示所有需求、所有字段的独立表单。字段从当前卡片上下文创建，归属唯一时自动带入；多义时就地选择或创建具名需求。全局需求管理另有入口，但不是每次绑定字段的前置步骤。

布局保留已有原生浏览器与可调分栏。宽屏可用列表+浏览器+按需详情；窄屏打开详情时折叠列表或换侧栏内容，不能四层横向嵌套把浏览器挤没。只维持一个主要滚动编辑面板。最小窗体1100×760与默认窗体都要验证，不能靠增大窗口掩盖控件不可达。

### 3.3 存档页首屏应解决的问题

能看懂“哪一份任务、哪个版本、来自哪些录制、改了什么、是否被执行过”。资料版本按稳定顺序列出名称/编号/时间/作者/摘要和使用状态。点版本打开只读卡片/回放，而不是在可编辑草稿上方堆一个section。

原始录制条目默认“回放并查看相关保存点”；原件JSON、旧Checkpoint收据、hash和重建索引进入诊断菜单。诊断清楚标“原始采集收据（不可编辑）”，不再用另一份可混淆的“保存点列表”。

过滤某个录制只改变列表范围，不删除整份任务里其他录制的字段/需求。两个录制共同组成一个版本是必须测试的场景。

## 4. 保存点、字段与选择的应用服务

### 4.1 保留现有事务，新增清楚的语义返回

复用captureAndAuthor、material CAS、SelectionSession与source verifier。抽出一层窄的工作区命令，不让页面组件直接组合一大批跨域对象。命名可调整，但语义要固定：

- `getOrCreateWorkingCopy / openWorkingCopy / getEntityById`
- `createCheckpointFromLive / createCheckpointFromHistory`
- `saveCheckpointEdits / copyCheckpoint / removeCheckpoint`
- `beginSelection / commitSelection / cancelSelection`
- `saveArchiveRevision / deriveWorkingCopy / compareRevisions`

这不是新增另一套公开控制接口：统一到现有IPC/HTTP适配，并在确需对Agent开放的部分复用授权。

写返回至少带operationId、准确工作副本及修订、影响对象ID、created/copied/removed关系和推荐focus。复制后选副本并进入改名；删除后清空对应编辑或选择下一卡；保存后仍聚焦被保存对象，不回到第一页的任意对象。

### 4.2 编辑会话与读模型

不要继续用当前分页的 `pages.*.items` 充当全部资料数据库。列表只负责展示；选择对象按稳定ID读取，并同时携带project、draft/revision、expectedRevision/hash。

编辑状态可用小型reducer/typed store：viewMode、owner、selectedEntity、dirty patch、pending operation、selection purpose。异步回执先验owner，再修改状态；不经多个独立setState和closure传递整个旧实体。保存卡片、切草稿、切项目、复制、退出时采用同一保存/保留/取消协议。

可在后台防抖保存完整且合法的修改，但只能在宿主确认耐久后显示“已保存”；未完成表单与本机恢复缓冲标“未提交输入”。不要通过强制立即保存未完成字段来阻止用户选元素。切换不同工作副本的脏输入明确各自归属。

所有关闭/切换流程要覆盖：旧请求迟到、用户取消、服务端冲突、receipt已保存但未关联、发布清单已保存但副本推进失败。保留已修复的未知结果查询与幂等语义。

### 4.3 选择应有目的与可预测结果

按钮不是一个没有去向的全局inspect开关。进入时固定目的：添加字段、给某字段新增例证、重新选择某绑定、添加注释，或快速保存点标记。

- 从历史卡片操作：自动定位准确anchor、暂停、进入检查，返回该编辑器。
- 从实时页面操作：先固化选择时刻；若不同于旧卡片，不移动旧anchor。新来源的归属在返回时明确。
- 在同一冻结页面给一张卡片连续添加多个字段：复用该snapshot/anchor和节点映射，不每次制造同名“字段现场示例”。想改用新的实时状态时明确新增例证。
- 用户确需同一字段多个历史示例时，将例证关系独立保存（如fieldId、checkpointId、target、可选annotationId）。可沿现有格式增加版本化扩展/新资料格式并做读适配；不要把“追加”实现成覆盖唯一target。旧版本缺新字段不回填hash，迁移只在新草稿形成新格式。
- 不为达到多例证支持引入任意图编辑器；本轮仅实现查看、添加、移除例证及原有单例兼容。

蒙版禁止冲突输入，但取消/Esc、状态提示、全局停止必须可达。不要把取消按钮本身放入inert祖先。普通文字说明不强制绑定元素；字段绑定与额外注释各自可选。

## 5. 工作副本、版本与目录数据

### 5.1 稳定工作副本

在项目持久辅助目录保存默认workingDraftId及catalogRevision。`getOrCreate`在同一writer事务内执行；并发请求返回同一个默认副本，不创建多份随机草稿。

迁移已有多草稿时不猜测哪份可以删除：有可核验的当前本机选择则作为一次明确候选，否则按确定规则建议并让用户可选择。未选中的保留为具名“其他工作副本”，可管理。后续不用UUID字典序覆盖用户选择。

工作副本支持名称、来源版本、更新时间、作者、当前/其他/已停用状态。名称等目录元数据可在sidecar/canonical catalog中保存；不要为改名称重写旧固定版本。当前操作/编辑副本与Agent候选分别标识。

### 5.2 稳定版本目录

新版本在现有锁内分配单调displayNumber；存档清单的revisionId/hash保持权威。旧版本按完整集合的createdAt与ID作为tie-break建立一次稳定映射并持久保存，不能每页临时计算。排序和游标由同一服务提供，读取更多不改变既有V号。

用户可给版本标记名称/用途、比较、基于它继续编辑、隐藏/恢复；内容不可原地改。回退意味着新建工作副本，不删除后续历史。Agent候选没有用户确认就不能自动成为“当前接受版”。

只改变taskBrief的比较也必须有diff。草稿支持显式编辑taskBrief；项目目录objective变化不能偷偷覆盖已有草稿/固定版。字段技术映射此次仍复用当前实现，先把确认UI移到实现区；不要求同时完成所有mapping实体分离。

### 5.3 管理不应伤害历史引用

新目录层记录生命周期，但原始ID、hash、storageRef不变；索引/目录损坏与原件损坏分别报告。固定版本引用的来源不因列表隐藏/项目归档而失效。直接历史ID读取必须仍有正确scope和授权，不用“已隐藏”暗中扩大权限或绕过检查。

删除、复制、更新使用服务端完整关联图检查，不取当前加载的一页当全量依赖。所有目录写先构造候选→验证→原子持久→发布内存状态；失败回执不留下已生效的新项目/环境。跨文件提交用已有锁和可恢复操作清单，不引入无必要数据库。

## 6. 真正的数据管理：明确可做与不可做

| 对象 | 本轮要支持的管理 | 保护和历史语义 |
|---|---|---|
| 项目 | 列表搜索、改名/简介、选择、归档停用/恢复；未使用空项目可确认删除 | 查看历史不依赖项目仍出现在默认列表；有历史引用时保留目录身份，不递归删除原件 |
| 登录环境 | 改名、入口/说明/检查配置、打开/关闭/检查、停用/恢复 | storageRef/partition与账号数据不随改名改变；活动环境不直接删除或迁移存储 |
| 工作副本 | 设为当前、改名、基于固定版本创建、查看差异、另存副本、移除/恢复 | dirty处理、Agent候选与用户编辑隔离；有关联中的采集操作先明确收敛 |
| 存档版本 | 稳定编号/标记/备注、查看、比较、基于此版编辑、隐藏/恢复 | 版本内容不修改；执行绑定旧id/hash可继续读取；隐藏不撤销既有证据 |
| 原始录制 | 名称/备注/筛选、回放、相关卡片与使用版本、隐藏/恢复、诊断 | 改的是外部目录元数据，不改已封存manifest/blob；被引用不能物理删除 |
| 需求/字段 | 就地改名/含义、添加/移除关联、查看使用位置、删除前依赖预览 | 共享实体修改影响哪些卡片清楚提示；移除卡片不自动删除共享要求 |
| 保存点 | 改名/说明、复制、移位、删除、撤销/恢复当前未固定修改 | 删除的是工作副本中的卡片，不删除源录制；固定版不变 |

### 6.1 删除不是一句“有历史所以不支持”

正常整理应能完成：用户把不需要的项目/环境/草稿从日常列表移除，并在已移除视图恢复。使用显式生命周期目录记录这个动作，不偷偷删文件，也不能只在当前React数组中隐藏、重启又出现。

对于未使用且没有来源/执行/草稿/活跃会话关联的空对象，可提供明确二次确认后的真正删除。项目有历史引用时，默认是“归档项目”或“移到已移除”，保留原登记身份以支持历史读取。

永久删除原始录制、整份profile数据或共享资源不作为本轮自动动作。若界面提供清理选项，必须是单独明确的用户操作、活动状态检查、引用清单和不可恢复说明；没实现这套边界就不显示误导按钮。不要把清空登录数据当成删除配置的副作用。

### 6.2 环境检查与变更

编辑配置经CAS保存并增加configRevision，原检查结果注明旧配置、origin和时间；影响登录检查的改动后状态回到unknown。保存profile数据不等于登录verified。

普通配置界面使用业务名称/登录入口/说明，CSS检查器属于高级可选。支持明确的预期业务origin或范围；不能将当前错误页面上的同名隐藏节点当登录成功。检查失败、超时、页面已关闭、曾登录但过期分别有原因；失败更新不能保留“刚刚已验证”的旧状态。

仍只支持显式项目绑定的环境。首版不自动跨项目共享账号状态；需要复用时明确关联同一环境，并显示作用范围，而不是复制Cookie或偷偷生成新partition。

### 6.3 变更中的会话和授权

改名称不需要销毁浏览器。更改入口只影响下次进入，不自动导航正在操作的页。归档/删除活动环境或项目时，应列出受影响session/run/execution/task authorization；用户选择停止并关闭后才继续，或取消管理操作。不能为了完成CRUD强制终止现场。

管理权限默认可信UI；新增Agent管理API必须明确能力，不能把材料编辑授权扩成删除项目/清空登录环境。取消/撤销不被目录管理锁阻塞。

## 7. 内置浏览器：补基础能力，不以“不是浏览器产品”回避日常工作

### 7.1 已有基础应该完善而非重写

当前已有受管页面、弹窗父子关系、后退/前进/刷新、地址导航、关闭当前页，以及原生输入身份/遮挡规则。[S04][S09][S11]

本轮优先补齐以下行为，使用当前锁定Electron的WebContents、navigationHistory、Session能力，核对实际版本，不顺手升级依赖。[E01][E02]

| 能力 | 实现与验收要点 |
|---|---|
| 地址栏 | 聚焦/全选、复制、显式提交；可将无scheme的正常主机补成https；不把任意文本当脚本/本地路径，不擅加搜索引擎。页面跳转不覆盖正在输入的地址。 |
| 前进/后退/刷新/停止 | 真正使用canGoBack/Forward与loading；加载中“停止”是取消导航，不是停止录制；错误有地址、原因和重试入口。 |
| 标签 | 人类新建页、切换、各页关闭、恢复最近关闭的URL、标题/加载/错误；恢复URL不等于恢复JS会话。最后一页关闭后有可用新页入口。 |
| 页面查找 | 当前live页Ctrl+F、前后匹配、关闭；与工作区列表搜索分开；回放只读查找在受控范围内，不启用历史业务脚本。 |
| 缩放 | 显示比例、放大/缩小/恢复；live zoom和历史“适应画面”分开，录制布局身份受影响时正确记入采集元数据。 |
| 常用快捷键/菜单 | Ctrl+L/T/W/Shift+T/R/F、Ctrl+S保存工作区修改、Esc取消当前模式；键盘由明确目标处理，不同时关闭页面和注释框。 |
| 右键/链接 | 复制文本/链接、粘贴、在新受管标签打开；外部应用打开需可信用户动作和scheme检查，不让脚本跳出安全边界。 |
| 网页对话框/文件选择 | alert/confirm/prompt和上传入口有可见安全处理，取消可达；自动化中的对话框遵守原有人工交接与权限，不代人确认敏感提交。 |
| 下载 | session级下载列表/进度/失败/取消/位置；是否录制不影响基本下载操作。录制时导入证据仍是独立、有限的过程，不能因此自动打开可执行文件。 |
| 网站权限 | 保留默认拒绝，但说明被拒原因；支持范围内由可信用户按origin决定。没有明确支持的权限保持拒绝，不为修登录关闭webSecurity或整体放行。 |
| 浏览器与业务状态 | 实时/历史、录制/未录制、人类/Agent控制始终可见；页面加载失败与引擎/采集失败不能混成一条“操作未完成”。 |

后台页面读写继续按page/target/session/generation/lease绑定，不能为了新增快捷键或按钮绕过已有检查。面向人类的新页命令与Agent受授权建页共用安全的底层分配器，但不同授权入口；无活跃录制也可用。

### 7.2 统一可回滚的页面分配

对addPage创建的native view、事件监听、Puppeteer target、capture和登记表分别取得ownership。等待target、capture.start或其他初始化失败时清理本次分配，不关闭别人的环境。真实网站导航报错可以保留一个明确的错误页并允许重试；内部会话初始化失败则清理或进入明确可恢复状态。

`createTaskPage`的try边界应覆盖初始化，且能够拿到局部分配句柄；只把await挪进try但仍找不到需要清理的view不算完成。最终恢复mask/presentation要根据最新owner/controller/overlay，而不是无条件unlock。

失败回归至少包含native view创建后、target等待、capture开始、授权页登记、初始导航失败。原环境/其他页保持，重试无孤儿view或重复监听，旧生命周期与取消回归不退化。

### 7.3 状态和事件组织

服务端PageState给出url/title/navigation flags/loading/loadError/zoom等实际状态。刷新状态用事件订阅或已有有界更新机制；保留必要回退轮询，不每2秒整份世界状态覆盖正在编辑的上下文。

命令带session/page身份和代际，UI过期响应不能改变新标签。app级快捷键在实际WebContents与可信窗口路径上路由，不从不可信网页消息接受“关闭项目/授予权限”指令。

全局“停止自动化”固定在顶栏或会话栏，不随保存点/存档/结果切换消失；选择蒙版和modal必须为它留路。停止只在相关控制动作静默后说明可接管，不把解除遮罩当成取消已执行命令。

## 8. 代码拆分与最小迁移

### 8.1 先固定边界，不机械按文件行数拆分

推荐在现有目录内形成：

| 责任 | 推荐归属 |
|---|---|
| 顶层导航/项目浏览上下文/全局停止 | AppShell及其typed view state |
| 当前工作副本指针、目录、管理事务 | main侧ProjectWorkspace/Catalog服务，复用现有存储锁 |
| 资料内容、CAS、来源关系 | 现有ProjectMaterials/FileMaterialService，增加必要领域命令 |
| 存档列表、版本只读、比较/派生 | ArchiveCenter，和原始证据诊断视图区分 |
| 保存点列表、卡片摘要、单字段/注释编辑 | CheckpointWorkspace及一个EditorSession控制器 |
| 选择、历史定位与来源展示 | 复用SelectionSession、ReplayHost、SourceTarget读取 |
| 浏览器标签/导航/命令/页面分配 | session/browser服务；UI只是投影和命令发起者 |
| 实现映射、运行、结果 | 现有实现/结果模块，不混进卡片默认编辑表单 |

不把main的大量权威状态复制到前端私有“新版模型”。API/IPC返回只给所需身份、状态和摘要，不用any掩盖哪个对象被改变。两个相互替代的UI入口在迁移阶段短暂共存可接受，交付时不保留两套普通保存点编辑流程。

### 8.2 兼容规则

- 默认工作副本指针和目录可以新增，但旧draft/revision ID、hash、原始录制路径、partition不能重建。
- 旧无名称对象显示可理解的临时名称，并允许用户保存目录名称；不修改历史内容。
- 旧V号若仅是过去客户端临时计算，不当成可信持久身份；建立稳定显示编号时说明历史显示可能调整一次，机器ID/hash不变，以后稳定。
- 字段多例证或内容schema升级仅对新草稿/新版本，旧版本继续用旧解析/哈希语义。不能读取时统一写回默认字段。
- 有活动authoring operation的草稿，处置前读取操作状态与receipt。取消界面不删除已落盘原件；恢复有明确所有者。
- 重启/进程退出时，编辑缓存与服务端草稿分别处理。管理目录已更新而内容提交失败，显示可恢复的准确阶段，不宣称全成功。

## 10. 下一步工作包与并行方式

### W0：确立当前模型并落入代码

核对现场、文档入库；将视图模式、工作副本指针、版本目录及管理状态的最小接口落实，保留旧读适配。先提交可运行的shell：默认保存点页与存档页真正分离，当前模式明确，不先交付只有截图/空页面的“设计完成”。

W0不需要新的多轮S0或全仓再审查。已知问题在当前文件定向读取，失败证据保留。

### W1：保存点与存档闭环（一个负责人）

完成第3–5节：集中编辑、明确选择目的、命令回执/focus、固定版只读、比较/派生、稳定编号及exact-ID读写。多例证按最小关系完成旧单例兼容。高频操作在真实原生浏览器/回放上验证，不能只在React mocks里成立。

### W2：管理与浏览器（最多两条独立实施流）

W0接口稳定后，可并行：一条项目/环境/副本目录管理与失败回滚，一条浏览器session基础能力及安全页面分配。AppShell、Studio集成根、公共schema、package/lock各有唯一owner，不能两个任务在同一文件里各搭一套方法。

主任务负责W1时，最多再开两个真正独立上下文，避免昂贵主控只做Git传话。桌面测试排他，但等待桌面不阻止别人在独立树写代码/跑模块测试。无需固定某款模型写进AGENTS，也不默认Ultra或递归派发。

### W3：综合用户验收与交付

先做14中的对象辨识与快速任务，再跑T1–T3相关回归、管理失败/历史保护及浏览器边界；最后以新构建做独立空根使用。让用户看到可运行的新布局与完整路径，不把三个大包各自通过当成一个产品通过。

这次用户已明确授权管理和浏览器方向，不再机械套“不得做M2/M3”的旧停止点。但不自动扩大到任意浏览器能力、长期长测、云同步或重做整个验证体系。完成本文件与14的范围后，提交并交付等待用户确认；真实权限/账号/不可逆清理才提出最小请求，其余继续。

### 交付必须包含

当前源/实际构建SHA、14验收表、已关闭UX编号、迁移方式和旧hash/partition保护结果、已提交文档清单、未测/故障边界以及普通启动方式。模块、Electron输入、独立使用者与用户确认分层说明。

不把“有一个按钮/接口”“测试数量变多”当作完成。提交前核对当前构建不是上轮42ccf54；能复用的旧证据注明范围，变更的用户路径必须实测新候选。
