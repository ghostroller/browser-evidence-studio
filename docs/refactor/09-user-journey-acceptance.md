# Browser Evidence Studio：用户旅程验收与交付规则

日期：2026-09-27。配套：`08-product-realignment.md`。本文件检验产品是否可用；不取代封存、权限、取消、损坏恢复等低层回归。

## 0. 验收不能再绕过正在验收的产品步骤

**产品旅程必须由空的隔离 BES_DATA 开始，使用真实可见的应用 UI 创建任务、环境、保存点、需求、字段和版本。最终验证的必须是这一路创建的同一版本。**

允许：启动合成网站、进程启动/关闭、模拟可见 UI 的真实用户输入、读取状态/磁盘作只读核验、取得截图/回放证据。允许模块测试直接调用服务，但必须单独标为模块测试。

不允许在产品旅程中：通过内部 `studio.createProfile/startRun` 或 `dispatch(...,'ui')` 预建被测业务数据；写文件补 dataset/sourceProof；直接操纵 React 状态绕过输入；借用另一个 fixture 的 executionId 来证明当前新建任务可运行；把按钮显示成功或命令返回等同于业务资料已持久。

历史 workbench 与 AT39 测试继续保留，但分别标明其前置：预设现场/任务资料后的组件和 Agent 接续验证。新产品验收不是用新名字重跑相同夹具。

## 1. 最小合成站点与真实环境边界

用一个本机“订单后台”即可覆盖大多数首批行为：登录页、受保护订单页、两页共若干订单、详情页；两个账户的数据不同；有重绘、弹窗与相同标签多实体。服务端不得为应用测试自动建环境或资料，只提供站点行为。

使用合成 Cookie，不读取用户真实账号。站点具备普通页面读标记以验证登录状态；保留 session-only Cookie 与可持久 Cookie 的差别。输入框含隐私哨兵，需确认默认不录登录且受限数据不进入普通交接。

后续增加同源 frame/open shadow、动态属性/样式、50+关系依赖、缺失资源与历史档案。不以一个简单页面宣称所有网站可恢复。真实用户档案在获得授权后本地只读检查；不上传或纳入 Git。

## 2. M1：六条必须首先跑通的操作

### U01：先准备登录环境，不强制开始录制

前置：空 BES_DATA。

1. 在 UI 创建一个任务，名称与自然语言目标随意，不输入内部 ID。
2. 创建登录环境，填写名称、登录入口和可选说明，点击“打开环境”。
3. 确认浏览器打开、录制指示为未录制，任务没有自动生成一段包含登录的示范。
4. 人工完成合成登录，执行检查并保留环境。
5. 关闭并重新打开环境，检查已持久状态；登录失败/过期时明确显示需要准备，不伪装 verified。

断言：无需先创建 Recording/EvidenceStore 即可工作；用户能找到环境配置入口；保存操作与登录判断分开；允许浏览但无后台业务录制。测试后只读检查 storageRef、会话和记录数量。

### U02：实时“记录当前结果”立即成为同一张可编辑保存点

1. 在已准备的页面开始示范，操作到订单列表。
2. 点“记录当前结果”，立即在统一保存点列表中看到新增卡片。
3. 填标题/说明，切换到存档再回来，内容保留。
4. 点“查看来源”能看到对应原始材料，再回到该卡片，不创建第二张同义卡片。

断言：一份用户卡片、一条可追溯来源关联；不要求再打开任务资料手动新建；operationId重试不重复；原始采集与编辑时间分开。

### U03：实时元素→字段，无附加注释

1. 从当前卡片点“添加所需字段”，选择页面金额元素。
2. 应用显示已选对象、所属卡片/需求，输入字段名称与含义；必要的数据集名称有默认值或普通可选项。
3. 不填 sourceProof、不填 XPath、不输入注释，保存。
4. 刷新资料、关闭并重开应用，在同一字段看到示例并能定位原历史节点。

断言：点击结果已成为耐久 HistoricalElementRef，不只存在 active.selection；UI、MaterialContent和执行器使用一致 dataset；字段注释可为空；快照原件存在且可检查。选择期间不能触发原站按钮、改变其原 inline outline或提交表单；Esc可退出。

### U04：注释/字段编辑互不污染，切换不丢数据

1. 编辑已有字段 F 的说明但暂未主动保存，切换 tab/卡片再返回。
2. 给另一元素新增普通注释，再返回 F。
3. 取消一次重新选择；再只修改 F 的描述并保存。
4. 显式点击“解除绑定”并确认，验证只有此操作删除 binding。

断言：F 的 ID/目标/注释关系不会因浏览卡片或普通注释改变；dirty状态被保存或明确询问，不能无声消失；同一卡片重新点击不清绑定。覆盖 P05 原始路径，不仅测试两个新字段。

### U05：停录后查看、编辑并形成固定版本

1. 停止录制，当前浏览器页面保留。
2. 进入存档，在历史位置新增一个保存点/字段说明；编辑之前 U02/U03 的卡片。
3. 保存并固定为 V1，然后复制/修改一个卡片，固定为 V2。
4. 分别打开 V1/V2，确认旧注释/来源与新版本互不覆盖，原录制哈希没变；复制后再改标题仍保留 derivedFrom。

断言：用户只维护一套保存点；资料版本显示可理解序号；未录当时可按完整历史补点；所有操作在同一资料工作区完成，不需要重新人工录制。

### U06：用刚从 UI 创建的任务执行，不借另一份预设成功资料

1. 完成 U03/U05 后点击“交给 Agent”。应用展示目标、数据集、字段、范围、例证和缺口，处理未保存内容。
2. 固定当前版本并授权任务。Agent从导出入口读取该版本，提出实现映射/普通代码，应用以可读形式展示。
3. 对已准备的环境执行。相同 UI 资料上的正确数据进入实际数据集；故意错误值被真实来源/关系规则识别；缺失验证依据保持未核验。
4. 用户能在结果页查看数据、失败/未核验原因，并定位到同一需求和保存点。

断言：requirement.dataset不是空；fields、binding、输出指纹和本次UI版本一致；不允许测试器写 sourceProof或第二份需求集。可以由真正Agent或被明确标记的实现器提供技术映射，不能由夹具绕过普通创建/确认路径。

**M1通过条件：U01–U06全部成立，并记录一段连续实际窗口操作证据。** 单项截图、白屏切换次数、单位测试数量不能替代这条连续路径。保留失败记录，但摘要要让用户看懂任务是否真的走完。

## 3. 后续完整验收矩阵

| ID | 场景 | 必须观察到的结果 |
|---|---|---|
| U07 | 字段三种输入：仅说明、绑定无注释、绑定带注释 | 均能保存，任务语义一致；前两种不被强制写注释/定位器 |
| U08 | 旧卡片与当前实时页面不同 | 默认新增现场例证或明确要求选择；绝不把当下元素挂到过去时刻 |
| U09 | 当前无录制，只想保存一个页面例证 | 有明确的单次取样/开始录制选择；不偷偷录登录历史；原件未成功时不声称绑定成功 |
| U10 | 旧 raw checkpoint 首次进入编辑 | 幂等派生统一卡片；可定位时用证据确定 anchor；不确定时说明编辑仍可用且绑定受限 |
| U11 | 60+字段引用某注释，目标在第二页之后 | 删除/重绑由服务端维护全部引用；未加载页不遗漏；保存后当前位置不跳成不存在 |
| U12 | 两个窗口/Agent并发编辑同一草稿 | 冲突保留本地输入，不静默覆盖；已发布版本不被修改 |
| U13 | 一个无关旧录制/资源/索引不可用 | 允许编辑另一需求的普通说明；来源状态清楚；不把失效绑定再标可靠 |
| U14 | 两次示范同一字段，多个例证 | 字段语义一份，两个例证可区分；追加例证不覆盖第一次；取消不破坏旧例证 |
| U15 | 用户先描述需求，尚无示范 | 自然语言任务和字段草稿可保存；不存在的证据不伪造；可以随后补录 |
| U16 | 任务目标/范围在V1后变化 | 新V2固定新的brief，V1实现不自动宣称满足V2；仅项目目录名字变不应混淆任务内容 |
| U17 | 停人工录制后Agent继续开发 | Session/环境仍可在授权范围用；执行建立自身证据run；不要求重开人工示范 |
| U18 | 人工接管、授权撤销、过期、页面关闭 | 合法读取不抢现场；旧写任务停止；真实取消后无迟到输入；重新授权路径清晰 |
| U19 | 登录环境编辑、切换与旧profile迁移 | 原partition不变，配置可独立打开；旧项目保持权限；不同账户不串数据 |
| U20 | 多项目显式复用同一环境 | 需显式关联且不扩大旧资料读取权限；默认不共享；切换任务不复制活动DB |
| U21 | 动态DOM、输入重绘、iframe/shadow、不同缩放 | 选择当前合法源节点；过期回执被拒；能力未覆盖区域显示具体原因，不静默绑定错对象 |
| U22 | 用户授权的原录制与日常目标页面 | 保留原件，只读复盘实际失败；独立记录格式/缺口/可用区域。未测明确，不以合成结果代替 |
| U23 | 最新安装包、完全退出再启动 | U01–U06在真实发行版成立；不依赖开发目录、内部脚本或预置BES_DATA |
| U24 | 真正新Agent从普通UI导出开始 | 不给预填dataset/proof任务或实现历史；根据固定资料完成实现、解释失败并修正，最后查看同版结果 |

“来源不支持/需要人工判定”可以是个别页面的正确结果，但不能成为绕过 U01–U06 通用路径的理由。现实网站缺资源与应用把入口断开是两类问题。

## 4. 领域状态表：测试正常组合，而非只测happy path

| 应用状态 | 允许 | 不应发生 |
|---|---|---|
| 环境未打开、无录制 | 编辑任务/字段说明，创建环境，查看已有存档 | 为打开登录页强制创建示范 |
| 环境已打开、人类控制、未录制 | 登录、检查、保存状态、开始录制、明确单次取样 | 虚构过去页面记录、自动把检查视为已登录 |
| 录制中、人类控制 | 普通操作、当前结果、实时选择、暂停/停止、资料编辑 | 选元素触发原站动作、来源失败却自动绑定 |
| 停录、浏览器仍打开 | 编辑/回放、保存环境、范围授权、试跑 | 因No active run让环境与授权入口失效 |
| 历史回放选择中 | 查看、选节点、注释/字段、取消、停止执行 | 对原站发网络/执行脚本、切换资料造成错绑 |
| Agent执行中 | 查询进度/既有资料、取消/接管 | 用户编辑新草稿覆盖当前执行固定版本 |
| 原件不完整 | 说明编辑、可用数据查看、明确补录/重绑定 | 自动把截图区当DOM、重新计算hash掩盖损坏 |

## 5. 保存、恢复和迁移的可验收协议

### 5.1 保存反馈

每个表单统一显示 idle/dirty/saving/saved/conflict/error。按钮或导航触发flush；发布/交接不能忽略未保存内容。用户离开页面时不隐式丢弃；明确取消只取消当前修改，不删除此前保存数据。

`capture-and-author` 类操作应返回原件保存结果和资料关联结果。原件成功而资料失败仍可重试关联，同一 operationId 创建至多一张对应卡片。不要为了所谓事务删除已确认原件。

### 5.2 新来源命令与普通编辑分开

新增/替换绑定必须核验当前来源和身份；只改标题无需重读所有旧源。执行时仍检查被引用证据，不以“曾经绑过”替代当前可用性。缓存以源/版本/hash身份约束，清楚列出不可用项。

### 5.3 迁移测试

使用合成拷贝：旧 project-profile partition、原raw checkpoint、单target字段、旧fixed revision和缺失资源。迁移前后逐项比原件hash、Cookie隔离、旧版本hash。重新运行迁移不重复卡片/环境/例证；未知task brief、dataset或anchor保持不确定，不以当前值填充过去。

## 6. 实施会话与检查责任

| 阶段 | 负责人 | 交付物 | 退出标准 |
|---|---|---|---|
| M0/M1 | Astra/high，直接实现，不仅调度 | 最小状态/命令契约、首条纵向流程、P04/P05/P06回归 | U01–U06真实通过、可运行演示；等待用户确认核心交互 |
| 并行展开 | Sol/high独立包；Astra看跨边界 | 环境、编辑关系与迁移、实现映射/接续 | 各自用户行为和相应U用例，不按文件数关账 |
| 独立产品检查 | 与实施者不同的上下文，Astra/high优先 | 只按任务说明/可见UI重复用户流程；报告阻塞、绕行、数据丢失 | 不知道内部ID也能完成，不能用调试工具修场景 |
| 回归/发行 | 当前集成负责人 | 影响分析、确切SHA的测试与真实包 | 旧安全约束保留、新产品路径通过、未测如实 |

不要把M0无限拉成长篇计划；首条可操作实现比再冻结几十个类型更有用。不要给产品检查者预设准确eventSeq、target selector或成功执行ID，它应通过用户可见内容找到对象。内部只读观测可以在失败后用于诊断，但不能修正产品状态让流程继续。

并行时只按已冻结的命令/类型拆职责；独立worktree、BES_DATA、文件所有权；同一机器桌面测试单令牌。主控不重新做所有子任务分析，不为Git/传话再开Agent。Windows本机直接执行所需测试，不引入Docker；仅在用户要求时触发GitHub CI。不自动push、清理旧树或修改全局配置。

## 7. 最终报告模板：不能只写“所有编号完成”

```text
候选 SHA / 安装包路径与 SHA256
本次用户能够完成的具体路径：U01..U24（逐项结果）
新资料来自何处：空数据根/可见UI/是否用了内部业务预置
本次执行绑定的资料revision/hash/代码与输入指纹
原件与旧profile保护：迁移映射、hash验证、未改写声明依据
底层测试：命令、结果、对应SHA；不能混用旧候选结果
未测/不支持/需人工：准确范围及原因
用户体验仍需确认：仅列真实未确认项
失败证据与接续点：简短索引，不回读全部历史
```

产品门未通过时，不用“基础能力已经完成”代替。后续通用风险/性能/格式扩展必须能指向实际用户流程或明确不变量，不再让工作无限偏回“修一批夹具、重跑全量、宣布完成”的循环。
