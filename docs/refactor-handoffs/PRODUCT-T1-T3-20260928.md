## 具体行为与限制

- `number + page-displayed` 不再允许确认旧精确文本映射。普通无映射草稿仍可保存；旧固定资料可读取，未回填新属性或修改旧 hash。旧 exact-text 逐字比较保持。
- 新映射为 `valueInterpretation: { kind: 'plain-decimal', version: 1 }`。只接受 ASCII 十进制、可选负号、无前导零；最多 64 字符、18 位小数，绝对值不超过 `Number.MAX_SAFE_INTEGER`，number 最短十进制表示须往返保持数值。尾零和负零不影响数值；空白、加号、指数、币种、千分位、百分号、单位、遮罩和有损精度均不猜测转换。实体 ID 仍按字符串逐字匹配。
- 宿主从当次采集原件独立读取可见采样，核对 execution/attempt、页面、frame、位置、实体和语义属性，再执行固定解释规则。脚本不能自报 normalizedValue 代替原件。错类型 fail；正确数值缺来源 inconclusive；旧不兼容配置以配置未核验说明，不能冒充观测到业务错值。
- 卡片 dirty 编辑先提交，再采集新样例；未完成字段缓冲不被强制保存。卡片新关联需求与字段明确所属需求分别保存。未知采集可暂存后编辑其他对象；查询或恢复不抢走当前缓冲。
- 宿主区分实际在执行的采集与磁盘遗留阶段。先找 receipt，再判 interrupted/unknown；读取失败不是“没有原件”。重启还会有界查找宿主 journal，不依赖 Chromium 缓存是否及时落盘。发现恢复最多扫描 500 个日志、返回 20 条/24 KiB；读取不完整有提示，不宣称所有旧日志已恢复。
- 结果读取 execution 固定版需求描述与字段名；“需求示例”与“本次验证来源”分别定位其真实录制/节点。诊断保留原文本、解释规则、期望、实际、批次、行和 sourceRef，每需求最多 20 条/12 KiB。旧报告不重写，缺新摘要时提示按原 execution 追加核验。
- 普通界面可明确设置期望条数及唯一标识字段；示例条数不自动成为全量断言。批次读取完整与业务全量证明分开显示；自然语言目标未被完整形式化时明确未证明。未新增任意转换 DSL。
