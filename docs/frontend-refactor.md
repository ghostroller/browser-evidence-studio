# 前端重构方案

日期：2026-09-23。本文先于实现落盘；当前已完成实施、自动化回归与截图视检。下文保留方案和验收标准，实际通过范围与待人工验证项见第 9 节及 [实际验证记录](verification.md)。

## 1. 目标与范围

将现有深色、三栏、卡片式工作台改为紧凑的工具软件界面：**左侧负责项目、录制与证据操作，右侧大面积留给内置可控浏览器**。实际引入 shadcn/ui 组件，统一交互和视觉，而非只在现有 CSS 上换颜色。

- 首次启动默认亮色，提供暗色切换并保存偏好；不随系统暗色自动改变首次默认。
- 主分界可拖动；保存点表单与列表、证据列表与详情等空间竞争明显的区域也提供可调整边界。
- 去掉项目名称首字方块、BE 装饰块、编号式引导图案、英文装饰眉题和营销式空状态。
- 去掉多层圆角卡片、渐变、阴影和无必要的大边距；用细分隔线、紧凑列表和明确的层级组织信息。
- 保留录制、控制权、checkpoint 取消、元素检查、脚本执行、人工交接、存档、回放、人工判定和异常恢复功能。

本批不修改证据格式、业务脚本契约和公共 HTTP 协议，不扩展长历史分页/回放定位、示范基线持久关联或真实账号流程。布局所需的可信 UI 显示与偏好桥接可以调整，但不能绕过控制权保护。

## 2. 现状依据

| 当前实现 | 问题及重构方向 |
| --- | --- |
| `src/renderer/app.tsx` 集中状态、布局、存档、回放与验收界面 | 按工作台、浏览器框架、证据阅读和偏好拆成少量组件，保留已有业务调用 |
| `style.css` 硬编码深色，含大量全局 button/input 和卡片样式 | 改用 shadcn 语义颜色、公共控件和有限布局样式，清除旧规则，避免两套样式叠加 |
| 左侧项目栏固定 220 px，浏览器右侧还有固定 304 px 操作栏 | 合并应用操作到左面板，浏览器放到最右侧，去掉固定第三栏 |
| 顶栏 66 px、大标题区、外边距 24 px、浏览器多层底栏 | 收敛为短顶栏、地址/页面栏和紧凑状态，优先浏览器高度 |
| 主面板、保存点和证据详情宽高固定或依赖外层滚动 | 各区独立滚动，使用有最小尺寸的可拖动分隔条 |
| 原生 `WebContentsView` 由 DOM 矩形经 `studio.bounds` 定位 | 所有尺寸及位置变化都必须同步原生浏览器和输入蒙版 |
| `showBrowser` 当前经过业务串行队列 | 弹层和拖动显示不能等待长 checkpoint；须与业务队列分离 |

本次开始时 `docs/environment.md`、`docs/progress.md`、`docs/verification.md` 和 renderer Vite 配置已有开发端口修复改动。期间另一任务将配置迁为 `vite.renderer.config.ts`，统一 ESM 并保留 `preload.cjs` 沙箱产物。本次接入保留这些修改以及 `127.0.0.1` / `port: 0`。

### 主分栏

- 左侧首次宽度按内容宽度约 30% 计算，限制在 320–440 px；右侧获得剩余空间，常用窗口下约占 70%。
- 左侧最小 320 px、浏览器最小 400 px；拖动允许临时加宽左侧阅读数据。窗口缩小时重新约束已保存比例，禁止面板挤成不可操作宽度。
- 保持当前窗口最小值 1100 × 760，重点验证 1100 × 760、1460 × 940 和最大化；不以提高最小窗口尺寸掩盖排版问题。
- 分隔条可见线约 1 px，鼠标命中区 6–8 px；支持键盘调整、清楚的焦点状态与“恢复默认布局”。
- 保存布局偏好，读取时校验数值并约束范围。拖动过程中只更新布局，不重建浏览器、页面或 profile。

### 左侧工作台

项目与登录环境使用紧凑选择器；新增项目/环境放在明确的新增入口中，不长期占据主工作区。保留项目切换限制和项目/profile 绑定关系。

| 页签 | 主要内容 | 空间处理 |
| --- | --- | --- |
| 保存点 | 标题、描述、稳定 key/需求 ID、保存/取消、已保存列表 | 表单与列表上下分隔；高级字段折叠；列表改为行而非卡片 |
| 元素 | 检查开关、选中元素文本、定位与来源 | 操作区紧凑，长结构数据独立滚动，可调整详情区 |
| 执行 | 脚本目录、输入 JSON、执行/停止、人工交接与当前结论 | 输入与结果区可调整；等待人工和 finalizing 始终明确可见 |
| 存档 | 本项目运行记录、读取状态、异常恢复入口 | 紧凑列表；选中后提供证据摘要与完整阅读入口，不增加固定第三栏 |

人工交接提示置于左侧可见区域，保留“交还控制”和“停止并接管”；错误使用可展开的内联提示，不用长通知挤占浏览器高度。危险操作保留文字说明，不只靠颜色或图标区分。

### 右侧浏览器

浏览器贴合面板边界，无外层卡片、投影或大圆角。仅保留页面标签、地址输入与必要状态；应用表单不再占浏览器右侧。

检查元素、暂停输入、暂停录制、授予/收回控制等现有操作放在紧凑工具条或左侧工作台明确位置。不会把“暂停输入”和“暂停录制”合成一个模糊开关。导航权限继续由当前控制者与执行状态决定。

空浏览器仅提示“选择项目和登录环境后开始录制”，移除装饰性徽标和三步宣传区。本次不增加尚未实现的前进/后退能力来扩大服务范围。

### 证据与验收阅读

完整材料阅读使用大尺寸 Dialog，明确返回工作台；打开时安全隐藏原生业务视图，关闭后恢复。Dialog 四周留 8–12 px，不使用厚重背板或巨大的标题留白。

- 保存点列表与材料详情使用可拖动左右分界；视口不足时改为可调整的上下分界或单列切换，保证内容可读。
- 截图、DOM/JSON、需求结果、数据表、人工评审使用统一紧凑排版。结构数据区域可以滚动、复制和按现有预算继续读取，不能靠截断掩盖内容。
- 长表格在自身容器横向滚动；保留字段名、状态和来源入口，页面本身不出现横向溢出。
- rrweb 回放保留原隔离和能力说明，不执行原站脚本。重构不虚构额外回放能力。
- 已知历史查询上限仍标注“当前已加载范围”；本次排版改造不等同于补齐长历史分页。

## 4. shadcn/ui 接入与组件替换

沿用现有 Electron Forge + Vite + React + TypeScript 单包项目。采用 shadcn/ui 的 Radix 路线、neutral 语义配色；不混用 Base UI/Radix 两套控件，也不创建新应用或 monorepo。

官方安装流程支持在现有 Vite 项目接入 Tailwind 和 shadcn 组件源码。将配置限定在 renderer：`components.json` 指向 `src/renderer`，TypeScript 与 Vite 使用一致的 renderer alias；保留当前构建输出目录、Electron preload 和动态开发端口。[Vite 接入](https://ui.shadcn.com/docs/installation/vite)、[CLI](https://ui.shadcn.com/docs/cli)。

文档阶段于 2026-09-23 通过 npm registry 元数据核对以下候选；当时尚未安装。实施时采用的实际版本与结果另记于第 9 节：

| 候选 | 查询版本 | 已核对的元数据 |
| --- | --- | --- |
| shadcn CLI | 4.21.0 | 非预发布版本；Node 要求 >=20.18.1 |
| tailwindcss / @tailwindcss/vite | 4.3.3 / 4.3.3 | 非预发布版本；Vite 插件 peer 范围包含 Vite 8 |
| react-resizable-panels | 4.13.2 | 非预发布版本；peer 范围包含 React/React DOM 19 |

候选版本来自 `npm view <包名> version dist-tags engines peerDependencies --json --cache output/npm-cache`。实施时固定实际采用的稳定版本，核对生成组件的附带依赖并更新 lockfile；现有 Electron/React/Vite 不因 UI 安装被自动升级。Node/npm 保持 24.21.0 / 11.19.0，版本管理器不限。

| 现有元素 | 替换方案 |
| --- | --- |
| 按钮、表单输入、文本域、标签 | Button、Input、Textarea、Label，统一尺寸和焦点样式 |
| 项目/profile/对照选择 | Native Select 或 Select；优先原生选择语义，确需 Portal 时接入遮挡管理 |
| 面板和存档页签 | Tabs，保留 selected 状态与键盘切换 |
| 状态标签与错误提示 | Badge、Alert；状态保持中文文本，不只用色点 |
| 项目高级字段、恢复详情 | Collapsible，常用操作不藏进折叠内容 |
| 设置、恢复、材料阅读弹层 | Dialog，受控打开/关闭、焦点约束、Esc 和返回按钮 |
| 分栏与详情布局 | ResizablePanelGroup / Panel / Handle |
| 长数据与评审记录 | Table、Scroll Area，必要时保留原生 overflow 容器 |
| 必要的短提示、分割线 | Tooltip、Separator；不使用 Tooltip 代替必要说明 |

shadcn 的 Resizable 基于 react-resizable-panels，并支持键盘操作；安装后按实际 v4 API 使用，不能照搬旧版属性。[Resizable 文档](https://ui.shadcn.com/docs/components/radix/resizable)。

只加入实际使用的组件。图标采用少量含义明确的 Lucide 图标，如设置、亮暗切换、展开/关闭；都附文字、aria-label 或可见提示。项目首字、BE 色块与无意义数字图案直接删除，不用另一批装饰图标替代。工作区不引入 Card 作为默认容器。

若 CLI 自动检测不能识别多入口 Vite 项目，先修正 renderer 路径和配置再重试；仍不适配时，按官方手动方式落入同一组件源码与依赖，并记录实际方式，不宣称安装成功。

## 5. 亮暗主题与密度

使用 background、foreground、muted、border、input、ring、primary、destructive 等语义 token；亮色为白/浅灰底与深色文字，暗色为中性深灰底，消除目前蓝绿装饰色和硬编码深色块。成功/警告/失败仅用于有业务意义的状态。[主题变量](https://ui.shadcn.com/docs/theming)。

| 项目 | 初始规范 |
| --- | --- |
| 字体 | 系统字体；正文 13 px，辅助信息 12 px；代码区等宽 |
| 顶部栏 | 约 38–40 px，无大品牌图案和副标题 |
| 常用控件 | 约 30–32 px 高，列表行约 30–34 px |
| 常规间距 | 4/8/12 px；面板内容默认 8 px，无整页 24 px 外边距 |
| 圆角 | 控件 4–6 px；工作区平直分栏 |
| 边界 | 1 px 细线；仅弹层使用轻微阴影 |

默认主题固定为 light，切换只影响可信应用 UI、窗口底色和原生锁提示；不对业务网页注入主题样式，不修改截图或全局强制业务页面的颜色偏好。沿用官方 Vite ThemeProvider 的组织方式，但明确覆盖其示例默认主题。[Vite 主题切换](https://ui.shadcn.com/docs/dark-mode/vite)。

偏好仅保存 theme 和允许的面板尺寸。由于开发服务器使用动态端口，单纯使用 renderer origin 的 localStorage 不能保证开发模式跨重启持久化；优先由可信 UI 服务将小型偏好保存在应用 userData 下，与录制、profile 和证据原件分开。读取失败回退亮色与默认布局，校验枚举和尺寸，不暴露任意路径读写。首帧应用主题，避免首次亮色启动先闪现旧深色背景。

## 6. Electron 原生视图适配

这是本次重构的必要部分，不能仅以浏览器中的静态页面预览验收。

1. **边界同步**：主分栏调整、面板折叠、窗口尺寸/位置变化、弹层关闭均统一测量 `.native-browser`。使用逐帧合并的布局更新，拖动结束补一次最终测量。原生浏览器和输入蒙版始终使用同一矩形；main 校验有限数值并约束到内容区。
2. **跨视图拖动**：DOM pointer capture 不作为已证明能力。拖动开始需让原生页面暂时不能接收这次鼠标操作；优先验证独立的布局遮挡/隐藏方式，释放后先同步新边界再恢复显示。pointerup、pointercancel、失焦、组件卸载均清理拖动状态。
3. **遮挡合成**：Dialog、下拉 Portal 与拖动共享一个可信 UI 显示协调入口，按遮挡原因合成；关闭某个弹层不能把另一个弹层下的浏览器提前显示出来。纯 UI 显示请求独立于长业务队列，并保留准确主 frame 校验。
4. **控制权不变**：布局遮挡与业务输入锁是两个状态。拖动、切主题或关闭弹层不能改变 controller、leaseEpoch、checkpoint 锁或人工等待；恢复可见时仍按当前业务锁显示原生蒙版。
5. **不重建会话**：调整尺寸不重新挂载 WebContentsView，不导航、不点击、不重置页面/profile，不重启录制或 runner。遮挡期间脚本/网络继续；需验证现有 Puppeteer 与采集不因新的不透明覆盖而卡住。
6. **回放隔离**：Dialog 或新组件不能把 preload 桥接泄露给 rrweb iframe；继续拒绝原站脚本与捕获 HTML 的内联执行。

## 7. 代码组织与实施顺序

采用少量职责明确的文件，按需要拆分，不引入全局状态框架或通用表单 DSL：

```text
src/renderer/
  app.tsx                       状态协调和主要布局
  components/ui/                实际引入的 shadcn 组件
  components/workspace-panel.tsx 左侧项目、操作与存档入口
  components/browser-pane.tsx    页面栏、地址栏、原生视图占位
  components/evidence-view.tsx   保存点、材料与回放阅读
  components/validation-view.tsx 结果、对照和人工评审
  components/theme-provider.tsx 主题偏好
  lib/utils.ts                  cn 等小工具
  style.css                     token、全局基础与必要布局规则
```

| 步骤 | 可检查交付 | 进入下一步的条件 |
| --- | --- | --- |
| A. 文档 | 本文与进度入口 | 布局、组件和安全边界明确；实现状态保持“未开始” |
| B. 组件与主题基础 | shadcn 源码、renderer Tailwind、亮暗 token、偏好 | 类型检查/构建通过；不覆盖现有 Vite 端口配置 |
| C. 两栏工作台 | 左应用/右浏览器、拖动分界、紧凑表单列表 | 真实 Electron 拖动、尺寸同步和控制权检查通过 |
| D. 阅读与验证 | 重构证据/验收/恢复界面、亮暗截图、回归报告 | 现有功能行为和新增布局验收通过，更新实际记录 |

不把一次大量 CSS 覆盖当完成。新区域稳定后删除对应旧样式和装饰结构；保留有业务语义的标签，将测试从外观选择器迁移到角色、可访问名称或少量稳定的 data 属性。

## 8. 验收标准

### 视觉与空间

- 新偏好目录首次进入为亮色；暗色切换即时生效，重启可保持；无首字方块、BE 图案、装饰眉题和渐变大卡片。
- 1460 × 940 默认布局中右侧浏览器占主要宽度；1100 × 760 下项目/profile、主操作、主题和分隔条仍可用，无整页横向溢出。
- 左侧加宽能实际扩大输入、表格和详情空间；表单与列表分界可调，内容各自滚动，控制按钮不被截断。
- 保存两种主题下的空工作区、录制中、材料阅读/验收和恢复界面截图，逐项视检。

### 原生行为

- 使用真实鼠标从分隔条拖入原生浏览器区域并释放；浏览器矩形与 DOM 占位误差不超过 2 CSS px，底下网页没有误点击，拖动无卡死。
- 键盘调整、快速连续拖动、窗口缩放/最大化、拖动失焦和恢复默认布局后边界正确。
- 打开/嵌套/关闭 Dialog 或 Portal 时遮挡正确；采集中仍可取消，关闭弹层不会解除 checkpoint 或 agent 输入锁。
- human、agent、waiting-human、finalizing 状态下布局和主题操作均不更改控制权、lease 或业务状态。
- 原生页面定时器/请求、普通 Puppeteer 运行和连续采集保持既有行为；回放 iframe 仍隔离。

### 原功能与工程

- 项目/profile 隔离、保存点及部分失败、脚本执行与取消、人工交接、评审回读、存档恢复和原件完整性继续通过。
- 保留 `npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run test:integration` 入口；布局/主题用例加入现有 desktop 场景，不另造一次性测试入口。
