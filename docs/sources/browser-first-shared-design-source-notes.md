## 可见正文的结构

1. 当前代码边界：preload 桥接较薄；Studio、浏览器宿主和回放仍依赖 Electron；原生视图与 React DOM 的两层呈现增加布局成本
2. 三类浏览器对象：工作台、受控业务目标、隔离历史回放不能混同身份
3. 目标架构与取舍：共享 React 工作台、类型化应用接口、共享用例服务及 Electron/Chromium runtime；先改善日常反馈，再扩大迁移
4. 三条安全/迁移边界：工作台权限与 Agent API 分离；旧 profile 不直接交给外部 Chromium；回放文档继续隔离
5. 一手参考：Electron、Playwright、Codex 浏览器、Chrome、OpenCode、VS Code 和 OpenAI harness 实践
6. 反馈循环与验收问题：真实可视反馈、少量关键界面基准、功能通过与交互质量的区别
7. B0–B4 路径：先验证工具可观察性，再接真实服务、提取回放，最后按收益决定独立 Node/Chromium 与双端维护
