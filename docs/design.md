# 产品设计：Browser Evidence Studio

状态：2026-09-29。当前行为以 [13 工作区/存档/管理](refactor/13-workspace-archives-and-management.md) 与 [14 交互验收](refactor/14-interaction-spec-and-acceptance.md) 为准；已成立的 T1–T3 保留。实际新构建验证见 [当前交接](refactor-handoffs/WORKSPACE-UX-20260929.md)。

## 1. 要解决的问题

网页为人设计。业务流程已知时，人操作一遍并说明关键结果，比让 agent 从入口反复探索更直接；之后 agent 负责补足参数化、分页、分支、数据来源选择和异常处理。最终产物必须是可审查、可独立运行的普通自动化代码，以及人能判断是否满足需求的证据。

本产品把三个角色接起来：
- 人：演示真实流程、说明需求、处理扫码/验证码、判断输出含义。
- agent：按证据编写和修正代码，报告未知项，触发复跑。
- 客户端：记录、查询、控制权管理、状态复用、执行观测和验收。

不把“一次成功点击”“拿到非空字段”“回放完毕”直接等同于业务成功。尤其区分登录成功、数据完整、字段语义正确和代码版本可用。

## 2. 产品闭环

~~~mermaid
flowchart LR
  A[创建任务与目标] --> B[独立准备登录环境]
  B --> C[示范与统一保存点]
  C --> D[绑定字段并固定任务版本]
  D --> E[Agent 提出普通代码与实现映射]
  E --> F[确认映射并授权执行]
  F --> G[检查同版数据与来源结果]
  G --> H[交付独立脚本及报告]
  G -->|失败或证据不足| C
~~~

原始演示仅说明发生过什么。需求由 checkpoint 描述和输出要求补足。比如人点击两次下一页，不能默认推断所有分页结束条件已经确定；agent 应指出需要的终止证据或补录变体。

## 3. 信息组织

任务沿用 Project；任务引用登录环境，环境打开 BrowserSession，录制与执行按需附着。用户只维护一套保存点与字段资料：保存点卡片关联不可变的原始采集收据和历史位置，固定任务版本关联后续实现与执行。

一个项目可有多个示范、需求变体、固定资料版本、代码版本和验收运行。Project.objective 是目录摘要，规范目标取固定版本中的 TaskBrief；旧版本没有固定目标时保持未知，不用当前项目文字回填。业务代码仍在独立脚本目录，客户端保存路径、指纹与运行引用，不接管其 Git 工作流。

- Run：一段连续会话，区分 demonstrate、validate；合成/真人/离线/代码实跑另有 mode。
- 原始 checkpoint：带采集时间范围、一致性及附件的不可变收据。
- 保存点卡片：唯一可编辑说明对象，关联精确历史位置、原始收据、需求及字段例证；修改说明不改原件。
- Requirement：需要什么数据、什么范围和什么结果，版本化保存。
- Annotation：用户或 agent 的解释，注明 observed/inferred/unverified，不篡改原件。
- Scenario：场景/变体标签，用于补录和覆盖；不是必须手工推进的业务阶段。
- Validation：实际构建、参数和环境上的执行与验收记录。

示范 checkpoint 与复跑 checkpoint 通过稳定 requirementId/checkpointKey 对应，不要求两次运行点击次数和中间页面完全相同。

## 4. 主要界面

主入口分为保存点工作区、存档、实现与结果；项目与环境管理、连接信息分别提供真实管理与诊断。默认工作区由服务原子准备稳定当前工作副本，只显示卡片摘要及一个按需编辑器。新增保存点创建卡片；保存修改/Ctrl+S仅写工作副本；保存存档版本在存档中心冻结资料。复制立即选新卡，移位/移除说明引用影响，原件和固定版不变。

存档区的资料版本、原始录制、工作副本互相分开。版本有稳定 V 号，打开后严格只读，明确派生才编辑；副本支持当前指针、改名、复制、差异、移除/恢复。录制默认回放并可查使用位置，原件收据/索引修复位于诊断。目录标签和备注不参与旧内容 hash。项目简介和固定 taskBrief 分开。

管理页创建项目只登记并选中管理条目，可立即改名或确认删除未使用的空项目；明确“设为当前浏览项目”后才准备默认工作副本。关闭管理窗不隐式进入该项目。顶栏快捷新建仍直接进入工作区。首次启动可选择已有项目；后续目录变化不自动抢占浏览项目。已有工作区的未保存输入仍需成功保存才能切换。

环境可独立打开、检查并保留登录状态，也可改名、配置、停用/恢复。项目归档可恢复；仅无依赖空对象可移除。有会话、录制、执行或授权的危险管理先显示依赖并显式收敛，不换 storageRef、不递归删历史。浏览项目 B 存档不接管 A 的活动会话，现场不会写入 B。

浏览器保留标签/子页身份，提供后退/前进/刷新/停止、错误重试、查找、缩放、快捷键、受管右键、下载和网站对话框。网站权限默认拒绝并显示原因；不开放外部协议或自动执行下载。全局停止和选择取消始终可达。页面状态推送驱动显示，原有页面代际、控制权与 sandbox/contextIsolation 仍校验。

开始录制等待 ready；暂停输入与暂停采集分开。结束录制保留浏览页面。当前录制未封存时，存档确认明确列出影响，只有用户选择结束此段后才封存并固定版本。部分采集/发布按原操作恢复，失败保留输入与原件。简单对象参数的标量 schema 可显示普通控件，复杂输入保留高级 JSON。

从卡片添加字段可直接选实时页面元素，不要求先切回放或手工另建卡片。先将点击源节点及位置耐久保存，再显示绑定成功；若当下与旧卡片不同时，新增现场例证，旧 anchor 不移动。历史选择自动定位卡片 anchor。选择中拦截原站输入、提供 Esc/取消，工具高亮不得改写业务元素 inline style。没有录制时需明确开始录制或执行受支持的单次取样，不能伪造此前登录历史。

编辑状态由项目、草稿和编辑会话共同标识。切 tab/卡片、取消选择不解除旧绑定或丢弃未保存输入；绑定命令明确区分保留、替换和解除。发布时冻结同一份未保存编辑，把卡片类型与关联、需求、字段和普通注释一次保存，再按该保存回执的修订固定版本；保存失败或冲突时停止发布。旧项目或草稿回执在修改任何当前编辑状态前核对归属，本机恢复输入不等于服务端已保存。用户填写字段含义，数据集可默认或选择，不填写内部 ID、sourceProof JSON 或实现定位器；技术映射由 Agent 提供并在应用内以可读形式确认。

## 5. checkpoint 的交互和一致性

保存时使用可实际覆盖 WebContentsView 的原生视图层或隐藏业务视图的快照占位层，不能只在 React DOM 上放一个遮罩。必须阻止鼠标、键盘快捷键、弹窗和 agent 写操作的竞争。

保存的两个阶段：
1. 快速获取当前 screenshot/DOM 及页面身份，持久化已获取材料。
2. 后台完成索引和相关请求关联，界面显示明确进度。

立即给出可见反馈。失败保留已成功材料，显示完整/部分/失败及补救方式；不能把索引仍在运行误报成未保存，也不能在持久化前显示保存成功。

蒙版不冻结页面脚本、网络、动画、二维码或服务端会话。材料记录 captureStartedAt、captureEndedAt、导航代际和一致性；如导航变化，标为 mixed 或重新采集一次，不能无限重试。

用户选中页面元素时进入检查模式：点击只选中和高亮，不执行网站动作。保存文本/角色/候选定位器/所在 frame/截图位置/DOM 来源，避免仅存易失效坐标。默认不收集密码和敏感输入明文。

元素隐藏/删除属于 P1 辅助能力，基础临时隐藏也不计入 P0；P0 只做检查、高亮和定位记录。后续先实现可撤销隐藏，记录 mutation 及受影响范围；不得将修改后的页面当作未经干预的原始证据。复杂页面重写不纳入首版。

## 6. 人机协作

一个业务浏览器同一时刻只有一个控制者。agent 等待人工时：
1. 先准备好需要操作的页面和最小说明。
2. 客户端进入 waiting-human，继续录制，显示让人做什么和何时结束。
3. 人直接在客户端操作，可连续完成一段流程，不逐个点击回聊天。
4. 人点击“交还控制”；客户端执行调用方定义的只读完成检查。
5. 成功才恢复脚本；失败显示原因并保留当前页面，允许重试、继续人工或取消。

二维码出现前不启动超长沟通等待；二维码过期作为一次新尝试。无回复或倒计时结束不能推断登录成功。超时进入需要注意状态，保留已有材料；不无限占用模型等待，也不自动反复刷新二维码。

运行、录制、控制权分别显示。用户可随时停止自动化并接管，客户端需确认 runner 已停止发出写操作后才开放人工输入。

## 7. 独立登录环境

环境配置保存名称、进入 URL、登录说明、可选只读完成检查及非敏感修订；持久 profile 保存网站状态；临时 BrowserSession 保存页面、导航代际与控制权。打开、检查、保留和关闭环境不以 Recording/EvidenceStore 为前置，登录默认不录入业务示范。“开始录制”只记录此后历史。

保留环境表示刷新可持久数据并记录 savedAt，独立检查记录 checkedAt、来源域、检查依据及 verified/expired/unknown；保留不等于登录验证。环境默认仅关联原项目，同一 profile 不并发使用。跨项目显式关联属于后续范围，不能默认共享 Cookie。

这不是任意页面的完整快照，也不保证所有站点会话永久有效。sessionStorage、内存 token、设备校验或服务端失效均可能要求重登；复用后必须由实际页面或脚本检查。登录是否有效记录为 verified/expired/unknown，不凭 profile 存在判成功。

旧 profile 的 storageRef 继续指向原 `persist:bes-${projectId}-${profileId}` partition，不换 ID 拼新分区，不移动或复制运行中的数据库。非敏感元数据迁移需备份并记录映射；旧录制和固定版本不改 hash。profile 不进入证据包；跨机器导出、全量克隆和 storageState 转换仍不承诺。

## 8. Agent 的工作方式和产物

公开本机 HTTP API。Agent 从可信 UI 导出的固定资料和范围授权接续，读取有界证据、取得受控浏览器权限、启动已登记脚本并查询结果。环境准备和任务确认由可信 UI 完成。授权绑定 project + session/environment + page + capability；无录制或停录后按当前 session 读取页面、执行获准动作及创建后台页，无需重开人工示范。页面写操作仍受控制权、导航代际、租约和取消约束；封存 runId 不能代指当前 session。执行建立自己的验证记录，无录制操作保存会话审计。不能暴露宿主文件系统或任意 Electron IPC。

浏览器探索 API 与脚本运行不是同一抽象：前者用于开发中的小范围检查，后者直接运行原生 Puppeteer。不要为了统一接口重新实现整个 Page。

产物包括普通 Node/Puppeteer 项目、锁文件、输入输出 schema、checkpoint 契约和独立启动入口。客户端的 reporter 可作为可选注入；脱离客户端也能运行业务代码，扫码可由独立入口承接。正常运行不依赖 LLM、客户端或临时 REPL 变量。

工具不负责将产物降级到 Node 14/旧 Puppeteer，也不负责嵌入 sky-eyes-app/cloud-data-forensic；这些属于其他项目的迁移工作。

## 9. 人类友好的验收

checkpoint 面板并排展示：人工示例、复跑截图、描述、输出数据、差异和来源。截图是辅助，结构化数据和业务断言是主要依据。

比较规则由需求指定：主键对齐、字段类型/必填、身份对应、去重、分页终止、跨页关联、范围覆盖。动态时间/余额/订单列表不默认要求像素或原值完全一致。历史固定样本可做精确对比，在线数据使用约束和语义检查。

含字段的需求必须有唯一且一致的 dataset，服务端在新草稿关联时补齐或拒绝矛盾；纯说明型需求可无 dataset。实现映射引用固定资料，提供字段输出路径和独立来源检查，不能降低用户语义或把样例值当验收常量。缺少来源依据保留未核验，不把脚本声明当通过。

2026-09-28 T1–T3 已修复此前独立复走发现的 number/dom-text 契约冲突：旧未声明值解释的映射继续精确文本比较；数值字段须明确使用版本化、受限的 plain-decimal v1，预览和确认检查类型兼容，宿主从当次原件独立解释并核验，不信任脚本归一化声明。旧固定版与失败报告不改；不允许私改字段为字符串、改变来源政策或放宽比较来获取 pass。实施者与独立普通用户各自从 UI 创建的数值任务均得到同版 pass/fail/inconclusive，独立完成最终退出重开；分段录像缺口及采集失败保留，待用户确认核心交互，不宣布 M1 最终完成。结果区分固定需求示例与本次实际来源，批次完整不等于自然语言业务全量。实际层级与证据见 [验证记录](verification.md)。

机器结论与人工判定分别保存。人工备注不能覆盖机器失败原记录；例外接受须说明范围和理由。未覆盖、证据不足和不通过分别可见。版本变化保留历史结果，但当前版本显示待重新验证。

## 10. 首版边界

P0 必须形成完整闭环：
- Windows 可启动的客户端、项目管理、内嵌浏览器和命名 profile。
- 连续动作/导航/网络/错误记录、关键截图/DOM、checkpoint 和元素标记。
- 两个 checkpoint 之间能查看按时间关联的操作、请求和关键状态；基础 DOM 回放复用稳定版 rrweb，M0 验证其边界。
- 有界证据查询和缺口提示；长录制不会要求 agent 全量读取。
- 本机 HTTP API、原生 Puppeteer 受控执行、人工交接和进度。
- 结构化数据展示、checkpoint 对应和版本化验收。
- 最小 agent skill、合成站点验证、可重新打开的本地存档。

P1：复杂 frame/Canvas/媒体等回放保真度增强、更细的视觉差异、外部标准浏览器运行模式、Playwright 业务执行适配、程序侧 HTTP 观测、脱敏导出/导入、可撤销页面修改增强。

不做：云端协作、完整 RPA 图编辑器、通用执行 DSL、自动生成所有站点规则、永久 AI 自愈、全量双框架适配、旧项目格式导入、插件装配平台。自有浏览器遇到目标站点兼容问题时如实标记，不保证能够规避站点限制。
