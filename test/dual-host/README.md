# B4 real-UI dual-host compatibility

Run on a Linux desktop with the repository's matching Node runtime and installed
Chromium. Build both entries first, then stop changing source/build files until
this acceptance finishes:

```sh
npm run build
npm run build:node
npm run test:dual-host -- --chromium=/absolute/path/to/chromium
```

`--host=electron`, `--host=node`, and `--output=/absolute/new/directory` are optional.
`BES_TEST_CHROMIUM` is an alternative to the Chromium flag. Output defaults to a
new gitignored `output/dual-host-<timestamp>` directory. An existing result file is
never overwritten. No account data or existing profiles are imported.

The runner serializes all visible activity. It starts the supported Electron
companion and explicitly opted-in cooperative Node launcher. A single fixture
implementation and HTTP origin are reused sequentially. The normal host UI
creates the project/profile and records actual 12→13→14 amount changes. After
sealing, the fixture server stops. The shared workbench's normal UI selects the
archived 13.00 event, clicks its real DOM node, creates the field, and publishes
and reloads a fixed version. Electron also reads that same source in its native
replay and fixed-version surfaces.

Both hosts execute identical `run.mjs` implementation bytes against their actual still-live
14.00 target. The only host-specific business input is the explicitly recorded
requirement ID generated by normal UI authoring. Each `workflow.json` also contains that distinct requirement ID, so the complete workflow/code fingerprint differs and is retained and verified for its own host. Good, wrong, and missing-source
variants select the actual dataset attempt and assert both source and overall
pass/fail/inconclusive verdicts. No hidden RPC or direct material write creates
any tested product record. Fixtures and standalone workflow files are test input.

The full report retains actual source positions, IDs, runtime samples, fixed
content hashes, outputs, diagnostics, target identity, process IDs, logs, and
screenshots. Comparison independently checks those relationships before mapping
only expected generated identities/timestamps. Unknown fixed-material content properties and properties of the compared diagnostics/records remain in the comparison; this does not claim every outer report field is identical. Original/fixed file hashes and complete source/build hashes
must remain unchanged. Owned launchers must drain and provider processes exit.

This is bounded compatibility acceptance, not a full platform matrix. Electron
recording starts after initial page load; Node captures before navigation. Initial
network coverage is therefore not asserted equal. Conservative CSS background
resource gaps remain visible and are reported separately. No physical input
exclusivity, universal interference detection, headless execution, or human
handoff is claimed for Node. Known old Electron native alert/confirm failures are
not fixed or relabeled. Legacy archive/profile tests are separate evidence and
are not implied by this runner passing.

## New synthetic legacy-profile check

```sh
node test/dual-host/legacy-profile.mjs --output=/absolute/new/proof-directory
```

This separate desktop test constructs new old-format metadata before application
startup, with omitted provider and a custom persistent partition. It opens only a
local synthetic cookie fixture and logs in through that fixture's normal form.
It checks same-process reopen, a second profile's isolation, and a different
Electron process reopening the same custom partition without another login.
No cookie database is read or copied, and no direct cookie setter is used.

At each `AWAITING_NATIVE_CLOSE` barrier, close the exact newly launched synthetic
Electron window through its native window controls. The marker contains its PID
and phase. Do not close another application. The test waits up to two minutes,
then requires matching `shutdown-complete` lifecycle identity and exit 0 before
continuing. This deliberate native action cannot be substituted by a hidden
business API. A timeout remains failed evidence. Old preserved archive inputs
are not launched by this test.
