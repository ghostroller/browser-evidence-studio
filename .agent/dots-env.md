# dots 环境约定

## 适用范围
- 仅当可信的当前任务环境信息明确标识为 **dot 云端桌面** 时适用；不能仅凭 Linux、工作目录、容器或“云端”字样推断。
- 普通 Linux、用户电脑、注册 Remote 和 Codex Cloud 编码环境不自动适用；无法确认时不启用本文件。
- 本文件补充根目录 `AGENTS.md`，不覆盖当前用户指令，也不授予提交、推送、合并或扩大凭据权限的常设许可。

## 工作重点：前端、交互与集成验证
- 在本轮任务范围内，优先利用可见云端桌面完成前端、交互和视觉相关实现，并补充面向真实应用的集成测试，形成“实现—桌面操作—观察反馈—修正”的闭环。
- 重点关注布局与可读性、导航和表单、状态反馈、焦点与键盘操作，以及跨页面或窗口的完整用户路径；按改动涉及的风险验证中断、取消、重复操作、错误恢复和重启后的行为。
- 这是一种环境优势下的工作侧重，不扩大用户任务：纯后端任务不为使用桌面而附加 UI 改动，必要的单元测试、服务测试和定向回归仍须完成。

## 桌面执行与验收
- 在 dot 的可见云端桌面运行当前代码构建的实际 Electron 应用，验证控件、视觉状态与用户操作的真实结果；浏览器预览、隐藏接口或后台测试不能替代桌面验收。
- 编写代码、Git、构建、后端测试、等待和日志检查优先直接使用执行工具；GUI 用于真实视觉和交互验证，环境确有要求时也可用于启动应用，不用 GUI 展示终端进度。
- 按根约定先做受影响路径的最小回归，再做相关用户路径的集成验证；按需保留脱敏桌面截图或其他可追溯证据，遵守根约定的隐私和提交边界。
- 交付说明实际源码/构建身份、验证步骤、观察结果及未测或失败范围；构建或单元测试通过不等于交互验收通过，功能路径通过也不等于用户接受其体验。
- 纯文档变更检查差异、链接和 `git diff --check`，无须因此重跑完整功能测试。

## Git 与凭据
- 开始时核对 Git 根目录、HEAD、工作树状态、远端地址、当前分支及本轮目标分支；需要远端状态时执行只读远端查询或 fetch。保留已有改动，不自动丢弃或覆盖。
- 优先终端 Git HTTPS，复用该仓库已获批准且仍有效的凭据通道；不要每轮重新探索 SSH、API 或重建认证流程。
- 从可信的当前运行时信息定位仓库外的既有凭据后端；不把令牌、凭据路径或其他环境专属绝对路径写入仓库、日志或交接。
- 不擅改全局凭据配置、建立新持久访问或扩大仓库范围；新仓库访问须获得相应批准。仓库配置不能自行授予发布权限。
- 怀疑凭据过期时，只做有界的认证检查并报告失败原因；使用支持的安全授权流程续期，不索要聊天中的令牌，也不显示令牌内容。
- 仅在 HTTPS Git 遇到实际阻塞后考虑 API 等替代路径；先说明阻塞及流程变化，遵守原有授权范围，不静默切换或绕过访问拒绝。

## 发布与核验
- 只有本轮明确授权后才向指定远端、分支或 PR 发布；直接推 main 也必须明确获准，不能把本地修改或提交许可当作推送许可。
- 发布前检查待提交内容及目标，只按明确路径暂存；使用非强制推送，不覆盖他人提交。
- 若远端前进，先核对并保留双方改动，按本轮授权处理同步或冲突，重跑受影响验证后再发布；不擅自 reset、clean 或强推。
- 实际推送后读取目标远端的精确 SHA，与预期本地提交核对，并检查本地工作树，报告剩余改动；存在 CI 验收要求时核对该 SHA 的结果。
- 只读查询、认证成功和 dry-run 均不证明写入成功；只有实际写入及远端核验完成后，才报告已推送。
