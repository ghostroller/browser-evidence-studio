# 京东账号证据采集

`run.mjs` 是普通 Puppeteer 业务入口。它只读取页面可见内容，不使用 Electron API、Studio HTTP、站点私有接口、CDP 命令或运行时 AI。脚本从演示记录中的京东专用登录页 `https://passport.jd.com/uc/login` 开始确认会话；随后检查可见退出链接或个人信息表单。只有两者均无法确认时才请求人工扫码。人工交还后先检查个人信息页，避免已登录时再次扫码；二维码过期时交还控制会重载登录页，最多尝试三次，交接等待时间为 10 分钟。页面显示的脱敏姓名和手机号会原样保存，不尝试还原。采集结果包含个人信息、地址、订单、截图和 DOM，属于敏感本地证据，不能提交到 Git。

## 客户端受管执行

在 Browser Evidence Studio 中选目标项目和登录 profile，在“执行 / 验收”将本目录登记为该项目的脚本目录，然后注册 `workflow.json`。API 不接受任意磁盘路径，因此注册必须从客户端的可信项目设置完成。启动受管复跑前，确认目标项目能列出这个 workflow，并核对 profile 和当前页面控制权。

输入可留空，默认采集当前日历年的订单；也可以给出一对包含首尾日期的 `startDate`、`endDate`（`YYYY-MM-DD`）。跨年范围逐年使用页面可见的年度筛选器，然后根据页面“下一页”的禁用状态或明确空列表判断分页结束。每条订单的摘要从对应列表行派生，并保留来源 checkpoint；当前执行不打开每笔订单详情页，也不声称采集了详情页独有字段。

录制档案显示回收站明确为空。脚本只在复跑页面再次显示“回收站暂时没有订单”时输出零条 `deletedOrders`；不会从其他来源补造记录。若页面出现记录，脚本会读取当前可见表格并检查字段与唯一订单号；非空回收站的分页方式没有在档案中观察到，不能据此声称已完整读取所有回收站页面。

个人资料、实名信息、地址、订单列表、列表派生订单摘要和回收站分别在本阶段读取及 checkpoint 关联完成后立即提交数据与断言，每个数据集只提交一次。地址导航从当前个人信息页解析可见的“收货地址 / 地址管理”链接，并在保存前要求页面出现地址卡片；若链接把页面带回首页，脚本立即报出明确错误，不会把首页误记为地址结果。最新真实 run 已确认历史地址路由会回到首页；基于当前可见链接的修正尚待一次新的受管实跑验证。后续阶段失败时，已经提交的数据仍可用于诊断；出错而未读完的阶段不会补交空列表或伪造完成结果，整个执行仍判失败。分页达到保护上限时保留已有的 `complete: false` 与终止原因，不能通过完整性验收。

## 脱离客户端运行

确认终端为 Node 24.21.0 / npm 11.19.0，仓库依赖已安装。独立入口使用单独的 Chrome 和新临时 profile，不读取或复制 Browser Evidence Studio profile：

```powershell
$env:BROWSER_EXECUTABLE_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm.cmd run example:jd-account -- --headed --start-date 2026-01-01 --end-date 2026-09-24 --output 'D:\private-evidence\jd-run'
```

路径应替换为本机 Chrome 和私有证据目录。`--headed` 用于人工扫码；若页面需要登录而未传该参数，脚本停止，不把超时或空闲当作成功。可省略日期参数采集当前日历年；可用 `--max-pages`、`--max-orders` 调整保护上限。独立运行会删除本次创建的临时浏览器 profile，输出目录保留数据 JSON、事件及每个 checkpoint 的 PNG/HTML。

## 录制证据和当前限制

受管模式在 workflow 中声明 `jd-login`、`jd-login-retry-2` 和 `jd-login-retry-3` 三个人工登录点。每次交还后脚本仍读取可见登录状态，不把控制权交还本身当作认证成功。三次重试仅通过合成测试，尚未在真实账号流程验证。

定位依据为演示档案 `efc0c4e5-e9b0-470a-8f0b-0ec5636f1c4f`。档案中记录了专用登录页 `passport.jd.com/uc/login`，并观察到个人资料页的 `#nickName`、`name="sex"` 和生日控件，地址列表路由 `https://easybuy.jd.com/address/getEasyBuyList.action` 与动态地址卡片 `[id^="addresssDiv-"]`，订单卡片及“订单详情”控件，回收站空状态，以及订单详情区域。真实 run 已显示这个历史地址路由现在会回到 `www.jd.com/`；后续执行改为查找当前个人信息页上的可见地址链接，并且仍须检查地址卡片后才创建 checkpoint。该导航修正尚未复跑验收。订单详情仅作为档案中的演示线索，本 workflow 目前不逐笔打开。

档案个人资料页没有可见的用户 ID 或登录名标签/字段。脚本不会把昵称、页面链接或账号别名猜作这两个值；复跑时若页面仍不提供它们，`profile-complete` 会失败。档案还只证明安全页可见“实名认证”和“绑定手机”导航/标签，真实姓名和手机号字段本身仍须受管实跑确认。脚本先读账户安全页，缺字段时再尝试对应的可见详情链接。演示回收站是空状态；非空回收站的跨页完整性也未验证。
