# Portable runner helper

`src/runner/portable.ts` is the single-file ESM build entry. The main integration build exports `.vite/build/portable-runner.mjs`, containing only the step/error helper and Node built-ins. The Windows application also exposes it as `resources/portable-runner.mjs` outside `app.asar` so a business project can copy it after Studio exits. Copy that helper and `run.mjs` into a normal Node/Puppeteer business project; install its own supported Puppeteer and lockfile. Runtime does not load Electron, Studio, Vite, an AI service or a second Page API.

`run.mjs` reads the repository's synthetic order-detail page using ordinary Puppeteer. Studio supplies `page`, `steps`, and an incremental `reporter`. A standalone caller supplies its own Puppeteer page plus awaited `onStep(event)` and durable `onData(batch)` callbacks. The standalone caller must own that page: timeout closes it before returning. With Studio, the main process instead revokes the operation connection and terminates the worker while retaining the live page.

For a selected rerun, pass `selection: { stepIds: ['orders.detail'], entityKeys: ['order-2'] }`, `priorAttempts: { 'order-2': previousIdentity }`, and `verifyRerun`. The callback performs fresh login/input/prerequisite/code/material checks with its AbortSignal and returns `{ valid, evidenceRefs, reason? }`. Missing or failed validation blocks the selected step. Successful validation is recorded with the old identity; actual execution gets a fresh attempt ID. This is a script-declared check, not independent acceptance.

Selection is applied in normal JS through `steps.selected()`; no workflow graph or branches are copied into JSON. If a business entry ignores selection, the helper cannot claim it implemented that request. New attempts do not overwrite old outputs. Reusing old rows uses the dataset service's explicit `reusedFrom` contract with validity evidence; rerunning this sample fetches fresh rows. Cross-execution row reuse is currently refused rather than silently trusting stale data.

The existing build integration/export location is owned by the main integration package. `runner-portable.test.ts` separately bundles this entry and executes it in a clean temporary directory using plain `node`, proving that the resulting helper has no repository runtime imports. It covers selected failed-entity reruns and failed compatibility checks; it does not replace the real browser fixture. An interrupted execution can reopen its same immutable binding and produce fresh attempts; code/input/material changes require a new execution binding and fresh compatibility checks.
